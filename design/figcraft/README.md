# PMLTWIN v03：M1 任务流程设计

主文件：`PMLTWIN-v03.figcraft`。从用户提供的 v02 另存制作，原件未覆盖。原有 12 页的根画板、侧栏图标、品牌标识、卡片、图表、双栏结构和导航均保留；只原位修正已审查的契约与状态文字，另外增加任务详情和恢复状态。保留 60 个 Theme 变量及 Light / Dark / High Contrast 模式。

共 15 页：原有 11 个工作页与能力二级页，新增 Form/Gadget 查询详情、组件与实现约定、18 个操作/恢复状态所在画布。后续评审、测试执行和 Web 管理的设计继续保留；实现按对应里程碑交付。设计示例不是运行证据，不为适配按钮改变现有接口。

## 三条流程

1. **会话**：发现 → 人工选择 → 核验 PID/启动身份/模块/专用管道 → 显示能力；无 Host、旧 Host、身份失效和读取失败分别反馈。
2. **注册函数**：选择真实 `.pmlfnc` → 核对全局声明与签名 → 默认拒绝 → 人工授予/撤销 → 参数预览 → 调用一次。源码变化后重新登记并重新授权；调度完成、业务返回值和结果未知分开。
3. **原生查询**：已显示/已加载窗体 → 控件清单 → 固定属性详情 → 按 NextIndex 续读。数组使用已有有界入口；空页仍有后续、末端、预算变化与 unavailable 均有单独状态。

Present 模式可点击侧栏、能力入口和关键操作按钮，打开状态叠层或进入查询详情。输入框中的值为设计示例；实际文件选择、校验和执行由 WPF 完成。页面中统一标注示意数据。

## 修正与复用

- 原有页面保留其构图，不用全局放大文字破坏排版。新增任务详情与 WPF 使用正文 14–16px、辅助信息 12–13px；原稿较小的文字在实现时重排。侧栏 232px、主区边距 28px、卡片圆角 18px、间距 18–20px。新增主次按钮使用原生组件实例与自动布局。
- 启动参数沿用 `LaunchService` 的 Monitor/Marine 格式；Host 身份在启动后的会话核验中确认。
- 函数示例改用合法全局名称与 STRING / REAL / BOOLEAN。对象方法不混入当前全局函数契约。
- 注册表只保存源码哈希，不保存旧正文；差异需定位 Git 历史，不凭哈希还原。
- 测试本次状态唯一；源码变化后本次显示证据失效，历史通过另列。点击详情可查看完整 ID、源码、目的、环境、命令、预期与证据。NET35 / NET48 Host 兼容、Native AOT Smoke 和 AVEVA 人工项分别分类。
- 评审由同一人工完成；实际源码差异、必需证据、开发/测试/正式目录、各迁移阶段和恢复范围分开。
- 日志先使用现有有界滚动记录；长周期趋势和健康度先定义统计口径。Web 按 M5a / M5b / M5b1 / M5c 分批。

`previews/` 为设计导出，不是测试结果。Dark / High Contrast 对会话、函数、查询三页导出检查；WPF 本批实现 Light 和系统缩放，主题切换仍为后续功能。小窗口采用滚动、双栏变单栏与卡片换行。实际 WPF 截图、原稿并排对照及验证回执位于本机 `artifacts/ui-fidelity-package`、`artifacts/ui-design-comparison`；人工易用性与 AVEVA 实机走查另行记录。

## 继续编辑与复刻

直接打开原生文件继续编辑。`v03-map.json` 记录页面/状态节点及 v02 输入 SHA256。可用已有 FigCraft CLI 重新生成：

```powershell
python build_v03.py --input '<原 v02.figcraft>' --cli '<本机 figcraft-cli.exe>' --output-dir '<新目录>'
```

脚本使用本机 FigCraft MCP 串行创建组件、画板、主题绑定和原型，再保存与导出；不会修改输入文件。生成后再人工编辑的内容不应被脚本覆盖，重新生成时使用另一个输出目录。
