# v0.3.0 — 本地知识分层与可靠升级

中文 | [English](v0.3.en.md)

本版是待 AVEVA 实机验收的本地候选包。执行 MCP、知识库 MCP 为 0.3.0；预置 Host 沿用 0.2.3 的程序集，避免无关的 Host 二进制变化。

## 三种独立数据库

| 用途 | 文件 | 来源与更新策略 |
|---|---|---|
| 项目库 | `knowledge/project.sqlite3` | 从本包的 PMLLIB/PMLUI 建立；用户请求安装或更新时自动重建 |
| 官方库 | `knowledge/official-<name>.sqlite3` | 仅从用户指定的本机官方 PMLLIB/PMLUI/WebHelp 建立；包更新完全保留，只有明确请求才重建 |
| 本地经验 | `knowledge/experience.sqlite3` | 通过工具追加用户确认的经验；包更新保留，不允许通过建库工具重建 |

三种数据库均不随发行包分发、不上传。注册官方知识来源不需要启动或连接 AVEVA，也不修改官方文件。不同产品版本应使用不同官方库名，例如 `official-pdms12.1`、`official-e3d3.1.6`，避免混淆接口版本。对来源目录没有读取权限时会报告失败，不修改旧数据库。

这里“项目库”专指包内维护的 PML 代码。额外的个人资料可用独立 `dbName` 保存，更新时原样保留。原有 `pml-knowledge.sqlite3` 不会被自动改名、拆分或删除；检索将它标为 legacy。如果旧库混合了官方和个人来源，可以另建分层库后再由用户决定是否删除旧库。

### 索引官方资料

在 MCP 中调用 `register_knowledge_source`，参数示例（路径应替换为本机实际目录）：

```json
{
  "role": "official",
  "name": "pdms12.1",
  "pmlLibRoot": "D:\\AVEVA\\PDMS12.1\\pmllib",
  "pmlUiRoot": "D:\\AVEVA\\PDMS12.1\\pmlui",
  "rebuild": false
}
```

`webHelpRoot` 可选。至少给一个来源目录。工具会登记来源路径并构建本地索引；若文件已存在，需明确请求后传 `rebuild=true`。包更新不会调用此工具或改动该库。

### 积累经验

调用 `record_local_experience(title, content, context, id?)`。context 应包含产品版本、项目/模块和验证依据；只记录用户允许保存的内容。相同 id 与相同内容的重复提交不产生重复记录；相同 id 的不同内容会报错，修正经验应使用新 id 并在内容中引用旧记录。不要把未经验证的推断写成已验证结论。

### 跨库检索

`search_knowledge_layers(query, topK=5)` 返回按数据库分组的结果，附 Role 和 Database。`topK` 是每个库的上限，不是跨库排名。引用片段时必须同时携带数据库路径和 chunkId，传给 `get_knowledge_chunk`。一个库损坏不妨碍其他库返回结果。用户应优先选择与当前产品版本相符的官方来源；本地经验不是执行授权。

## 更新及失败恢复

更新时复制旧 knowledge、trust 和发行包未包含的自定义 Profile，再交换目录。项目库构建失败则恢复旧安装目录和 Skill；官方库与经验库的字节内容保持不变。安装/更新最后才执行外部注册，两个 MCP 和 EVAR 先全部预检。

若第二个 MCP 添加失败，撤回本次尝试新增的配置；已存在且匹配的配置保持不变。即使命令已写入配置后返回非零，也会重新检查并撤回该项。若配置同时被其他进程改写，或撤销本身失败，会明确报告 `Rollback incomplete` 并保留部署文件供恢复，不会留下指向已删除文件的配置。

本版覆盖可捕获的脚本/CLI 失败。强制结束安装器、断电、硬盘故障不属于已验证的事务保证。卸载仍按原有流程删除受管理安装目录；需要保留知识和经验时，应先备份 knowledge 与 trust。版本升级不会删除它们。

## PDMS / AM 与 E3D

PDMS/AM 保留为传统产品支持，当前末版支持目标为 12.1 系列；本机现有 PMLNet、Aveva.Pdms.Utilities 参考程序集的文件版本均为 **12.1.4.0**。这是可验证的构建基线，不是对厂家最终发行版本的认定，也不意味着所有历史小版本均兼容。尚未执行 AVEVA 实机验证。

默认 AM/PDMS 使用 NET35；E3D 预置 Profile 使用 NET48。自定义 Profile 不再依赖名称猜测：注册器根据目录中的唯一 Host 写入 `YuzuhaFramework=net35` 或 `net48`。本地编译脚本也会提示同时设置 `Yuzuha` 和 `YuzuhaFramework`。手工配置自定义 Legacy Profile 时必须设置这两个变量。

例如：

```bat
set "Yuzuha=PDMS12.1Local"
set "YuzuhaFramework=net35"
```

## 验证

- 两个 .NET 10 MCP 编译与发布；知识库使用 Native AOT，旁置 `e_sqlite3.dll`。
- 知识库集成测试：三层检索、片段读取、经验追加与幂等、禁止经验重建、失败重建保留旧库、只刷新项目库。
- 生命周期故障注入：第二注册失败、写入后返回失败、预检冲突、已有 MCP 保留、成功更新的数据保留、失败更新恢复。
- PDMS/AM/E3D/任意名称 Legacy 的 EVAR framework 选择测试；不执行 Host。

所有测试均使用本地隔离目录和模拟的 Codex 命令，不修改正式环境。正式发布前仍需在目标 AM/PDMS 12.1 与 E3D 会话中完成加载、身份校验和明确授权下的 PML 验收。
