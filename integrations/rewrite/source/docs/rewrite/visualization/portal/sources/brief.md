# LaunchDesk 从零重写：共同产品输入

日期：2026-10-19。状态：架构比较；应用实现尚未授权。固定行为参考：`baseline/v2.0.4-before-likec4` / `3ffd635`。

LikeC4、OpenSpec、Archon 是三条并列的设计路径。各方案从本清单重新决定模块和契约，不继承旧源码的项目划分，也不要求另外两条方案服从自己的产物。本文件在 OpenSpec / Archon 分支保持相同内容。

## 必须支持什么

| ID | 用户需要的结果 | 需要避免的失败 |
| --- | --- | --- |
| R01 | Windows WPF / .NET 10；普通 EXE 在本机独立使用 | 开发编排或网络不可用导致整个工作台不能启动 |
| R02 | 应用与版本目录支持 AVEVA、PML AI 和通用程序；自动发现入口并允许人工指定 | 写死产品名、版本、`mon.exe` 路径，或扫描结果覆盖人工路径 |
| R03 | 登录配置支持新增、复制、编辑、删除、搜索、版本分类；项目、用户、MDB、模块可变 | 只有复制没有新增；分享后把他人的本机路径当成可直接使用 |
| R04 | 密码只在输入时按需显示；保存到 Windows 凭据管理器，运行时临时解析 | 已保存密码回填、明文日志、导出密码或本机凭据引用 |
| R05 | 同时管理多个许可；每次启动只给对应子进程注入变量 | 为切换版本改写全局许可变量，两个版本串用许可 |
| R06 | 许可监测包含本机服务、TCP 和虚拟机入口，瞬时失败复查、持续失败与恢复可见 | 一次超时就报虚拟机丢失；端口绿色被当成已签出许可 |
| R07 | 启动结果跨页面可见，区分检查、交接、窗口、未确认、失败和退出 | `mon.exe` 退出就当成会话退出；窗口出现就宣称项目登录成功 |
| R08 | 工具来源支持 ZIP / 7z、文件夹、普通文件与映射；刷新后可选最新或旧版包 | 强制先压缩；失去手动选择；刷新列表时误执行文件 |
| R09 | 工具更新先预览，再明确执行；支持备份、回滚、中断恢复与目标写入互斥 | 来源变更后仍执行旧计划；断电后自动重放；两个任务同时覆盖目录 |
| R10 | 工具变量支持新增、改名和作用域；持久应用与仅保存配置分开 | 无意改系统变量；重命名覆盖外部修改；工具覆盖许可专用变量 |
| R11 | 配置导入导出可跨机分享；导入只产生待确认的配置 | 导入时自动启动、部署、应用变量或执行包内脚本 |
| R12 | 数据目录可靠，可用 portable / 显式路径；升级保留 ID、关联、凭据和历史记录 | 打开目录失败；迁移损坏原文件；缺少配置时伪造成功或吞掉错误 |
| R13 | 图稿中的布局、图标、颜色、圆角、密码显隐及按钮状态形成可核对的 UI 约束 | 重写后视觉再次偏离 FigCraft；主要操作随整页滚动消失 |
| R14 | 预留多机管理和可替换编排；普通用户不必安装 Aspire / Backstage | 首版引入常驻远程服务；把框架类型或远程密码写入核心数据模型 |

## 两个编排选项

所有候选都必须能解释真实 Aspire 开发入口和普通 .NET 本机协调如何替换。它们应共用领域语义、状态、配置和行为测试；只在组合根与诊断适配器分叉。真实许可服务、AVEVA 与 VMware 是外部资源，不能因为结束开发会话就被自动停止。

## 本轮交付边界

先交付架构、取舍、接口草案、验收场景及可重复的设计检查，再由用户审阅。现有 C#、安装程序、生产配置、凭据、虚拟机和许可服务保持原状。从零重写允许重新划分内部结构，同时必须为旧数据和既有可用行为设计兼容验收。

## 比较方式

分别看：职责是否清楚、需求是否遗漏、失败后是否可判断、是否便于独立桌面使用、未来扩展代价、开发和维护成本。工具校验通过只能证明相应格式与已编码规则，不能证明未来程序已经正确实现。
