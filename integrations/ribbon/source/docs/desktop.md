# WPF 桌面端 · Ribbon 工作区 0.10

主窗口顺序为 **标题栏 → Office 命令 Ribbon → UIC 文件标签 → 编辑区**。左侧是结构树，中央始终保留当前文件的 Ribbon 预览，右侧编辑当前按钮的图标、Group、Macro 和 Tooltip。底部只有“按钮 / 查找”“UIC ↔ XML”“部署”三个停靠页。

设计源为 [ribbon-first-docked.figcraft](../design/figcraft/ribbon-first-docked.figcraft)，恢复 0.5 的 Ribbon 主视角。四张设计画板表示同一窗口的不同工具状态，不是四个页面。

## 最短流程

**加载 / 新建 → 编辑 → 检查并保存快照 → 按需部署。**

1. “加载文件”（Ctrl+O）可批量打开 UIC 或项目 JSON；“新建 UIC”（Ctrl+N）创建文件。文件标签各自保留选择、勾选、筛选和撤销栈。同一路径再次打开会跳转到已有标签。Ctrl+Tab / Ctrl+Shift+Tab 切换，Ctrl+W 关闭当前 UIC，关闭前记录草稿。
2. 在结构树或中央 Ribbon 中拖动菜单页、Group 和按钮排序；按钮可以跨 Group 移动。右键按对象提供剪切、复制、粘贴及编辑、布局子菜单。预览按钮不执行 Macro。
3. 右侧直接修改按钮名称、标识、图标、Macro、Tooltip；Group 和大小只作用于当前引用。名称、图标、Macro 和 Tooltip 在本 UIC 中的同一功能引用间共享。选择图标后由独立后端压缩到 Large 32×32 / Small 16×16，表格显示实际图标，不用尺寸数字占位。
4. 点击“检查项目”，修正问题后“保存快照”（Ctrl+S）。保存快照长期保留；编辑停顿约 900ms 自动保存草稿，只保留最近 5 次。编辑和保存均不会立即覆盖原 UIC。
5. 需要交付文件时点击“导出 UIC”；需要更新原文件时进入底部“部署”，选择文件和可复用配置，预览后明确确认。已有 XML 引用共享同一 UIC 更新，不必重复登记。

UIC 内的菜单页（例如 Ytools）是最终出现在 AVEVA 中的菜单层级，与上方浏览器式文件标签不同。“添加菜单页”属于 UIC 的 Tab → Group → 按钮结构。

## 底部三个停靠页

| 停靠页 | 常用操作 |
| --- | --- |
| 按钮 / 查找 | 当前 UIC 的功能对照表、筛选、详细列与批量修改；范围切换为已打开 UIC 后只读搜索并定位 |
| UIC ↔ XML | 从 UIC 查 XML 或从 XML 查 UIC，查看真实数量、产品版本、完整路径、来源与扫描诊断 |
| 部署 | 批量加入文件、复用部署配置、核对目标路径并预览所选 UIC 的更新或首次部署 |

当前文件表格可编辑单元格，或勾选多行点击“批量设置”。名称、Macro、Tooltip、图片、显示大小及目标 Group 可组合修改；未勾选字段保持不变。详细列仍位于底部，不替换中央 Ribbon。

跨文件范围只读：名称相同或 ID 相同的功能按来源区分，双击结果或点击“定位到 Ribbon”跳到确切文件和引用。批量修改始终限于当前文件，不暗中改写其他 UIC。

登记计数按 UIC/XML 路径组合去重，版本取实际 mon.exe 元数据或已标明来源的安装信息；未知显示未知。空结果不证明没有登记，完整扫描范围和未解析项可展开查看。从“管理登记”显式进入同一底部区域中的管理视图，再通过“返回登记查询”回来，不新增顶层工具标签。官方原生项只读；既有自定义项需显式接管，来源与后续部署记录持久化。

“更多 → 管理 / 历史”按需进入版本和加载条目管理，恢复先回到编辑器。部署和登记的实际写入继续独立预览、确认和备份。

## 撤销与重做

Ctrl+Z / Ctrl+Y 或命令 Ribbon 中的按钮回退当前 UIC 的操作。拖拽排序、跨 Group 移动、剪切粘贴、复制粘贴、图标和属性编辑，以及表格批量修改均可撤销；一次批量应用是一步操作，恢复原 Group 及精确顺序。

每个文件最多保留最近 50 步，只记录变化的属性和集合操作，不保存全量文档快照。切换文件保留其撤销栈；关闭文件、显式恢复版本或重启后清空。撤销只改变编辑状态，实际 UIC/XML 需重新预览部署。输入框有焦点时 Ctrl+Z / Ctrl+Y 仍处理文字；需要撤销文档时点击命令 Ribbon。

## 停靠、浮动与恢复

- 拖动底部页签离开停靠条，或点右上“⋯ → 拖出为辅助窗”。同一个控制器和筛选保留，重复打开只激活已有辅助窗。UIC 文件继续在主窗口编辑。
- 主窗口和辅助窗均可交互；辅助窗标题栏提供“停靠”和“单屏并排”，关闭辅助窗也会停靠回来。
- 拖回主窗口底部页签条时，蓝色预览只标示底部工具区和对应标签，松开才停靠；离开目标后清除预览。中央 Ribbon 不被覆盖。
- 拖动水平分隔条调整高度；“—”收起/展开，“↗”放大底部区。放大仍保留中央至少约 180px 的预览区域，适合大表格时可以拖出。
- 自动保存主窗、辅助窗位置和大小、停靠状态、当前工具、底部高度、收起状态和查找范围。正常退出立即保存，重启恢复；显示器断开后将窗口收回可见工作区。
- 布局位于 LocalAppData/RibbonStudio/Desktop/workspace-layout.json，与文档、撤销栈及后端业务记录分开。损坏配置留副本并回退。可用“更多 → 恢复默认停靠布局”重新排列。

## 构建与验证

在 UicRibbonDesigner 根目录执行：

~~~text
npm run backend:build
npm run desktop:build
npm run desktop
~~~

当前程序为 artifacts/desktop-workspace-0.10/RibbonStudio.Desktop.exe。启动器复用健康的独立 C# 后端，默认 http://127.0.0.1:4318；WPF 只通过 HTTP 调用，不引用后端业务实现，也不直接写 UIC/XML。

桌面工程为 apps/desktop/RibbonStudio.Desktop.csproj，目标 .NET Framework 4.8，无 WebView 和额外 NuGet 控件依赖。原 Office Ribbon 资源保留；自有控件模板、输入和菜单沿用统一色板及悬停、选中、禁用状态。主窗与辅助窗使用无边框 WindowChrome，文件选择使用系统对话框。

原生回归：npm run desktop:verify。隔离夹具覆盖批量撤销、精确引用定位、XML 去重/诊断、浮动停靠、1280/1050 布局与三个独立进程的重启恢复。仅测试夹具执行写入，不自动部署真实 AVEVA 文件。架构边界检查为 npm run architecture:check。
