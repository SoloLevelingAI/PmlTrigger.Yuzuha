## Scope

## Contract

### 1. 责任与阶段

顺序为：应用安装交接 → 选择本机产品环境 → 核对旧所有权/迁移来源 → 预览运行部署与EVARS → 明确应用 → 核对回执/必要恢复 → 配置与启动 → 严格会话核验和观察。用户可从已完成阶段继续；阅读位置、文件就绪、进程创建、Host可用、明确操作目标分别表示。

Inno SHALL交付应用、载荷清单、快捷入口及安装所有权，新交互流程默认选择管理器接手模式；安装完成可由原交互用户打开管理器准备任务。manager模式不得枚举后静默写厂商EVARS，不以none模式伪装完成AVEVA接入；旧显式aveva/none计划保持兼容。现有提权及安装升级政策不因界面迁移而静默改变。

管理器 SHALL复用已有`EvarsEditor`、`RuntimeDeploymentService`及OperationExecutor；WPF/CLI不各写文件引擎。Inno拥有的应用根不被管理器copy覆盖；引用模式复验包清单和bootstrap路径，自定义copy使用明确独立的受管运行根。安装包和运行部署可分别升级/恢复，不能把应用卸载当运行环境清理。

### 2. 输入、冻结与效果

输入为工具包根及载荷身份、选定产品/版本/入口/INIT或BAT、profile/framework、运行根及copy/reference模式。发现只读且有预算；歧义不自动选第一项。输入变化清除当前可执行预览，保留草稿；预览显示实际来源/目标、环境受管行、前后摘要、文件数量、所有权及恢复方式。

预览可保存非秘密计划缓存，不写业务目标。apply/restore SHALL显式授权并仅接冻结planId/sha256，执行前重验实际文件、安装身份和来源。成功表示计划范围内写入，不代表AVEVA加载；失败/部分恢复/unknown保留可定位回执，不自动重放。运行部署中的EVARS写入与单独EVARS编辑共享后端规则。

### 3. 旧所有权与迁移

对旧安装器拥有的环境修改先只读预览，显示安装所有者、目标和当前摘要；无法核对的旧格式/外部漂移明确拒绝。显式移交必须使旧卸载记录不再撤销已转交的目标，同时保存原记录及迁移回执；不通过删所有权标记、忽略冲突或改生产文件来伪造接管。只读rewrite/Next/Ribbon导入预览继续保持不激活；活动Database切换等原4.3/4.5任务未经过完整验收前保持未完成。

### 4. 人的操作动线与原生视觉

WPF SHALL提供显眼的“安装与环境准备”入口，Dashboard及安装完成可到达，输入在预览之前，主按钮随当前阶段改变；旧复制/函数/查询/设置保留为分支。首屏同时说明当前目标、会改变什么、下一步及结果位置；错误和恢复在动作附近，不要求用户通过JSON操作普通任务。转换页面/主题保留输入、选中目标、冻结身份及阅读位置，不自动触发写入或启动。

ION六套配色以同一JSON源生成CSS与原生XAML资源；映射现有语义key，显式转换RGBA/ARGB，保留状态色、焦点、禁用态、对比度及高DPI可读性。FigCraft保留可编辑来源/变量和对应板，不能只贴截图。视觉验收包含层级、密度、对齐、留白与动作可发现性；功能断言不替代视觉审阅，代理目检与用户认可分别记录。

准备任务中的同步扫描与文件IO在同一Manager执行器的后台调用边界运行，业务token原样传递，不因调度取消改变已有未知语义；状态回到调用方UI上下文更新。等待时锁输入和重复操作，真实Dispatcher仍可阅读，明确区分本次等待与上次已收到的回执，不能让旧成功冒充新完成。普通关窗保留进程并就近提示等待本次回执，完成后解除，不自动取消或重发。门闩因果验收在同步handler尚未释放前执行实际阅读导航、关窗保护及禁用/重复调用断言，不用Task.Delay伪造后台执行。

### 5. 完整契约到脚本及语言入口

建立只读运行契约清单：每阶段包含输入、前置、算法/调用、效果、校验、回执、恢复，绑定真实operation ID、源码类型/方法和DocFX路径。WPF的摘要/契约/脚本/证据栏目从同一清单读取；脚本解释决定、失败分支和能力边界，不能以源码行数或静态边当运行通过。

CLI SHALL以既有stdin/文件及授权机制提供契约读取/操作描述；稳定导出JSON、OpenAPI只读目录、TS输入类型和CLI适配示例。`OperationResult.data` 保持未知 JSON。21 项旅程操作可以另有公开摘要，摘要必须允许额外字段，不能把 data 收成封闭类型；透传操作不承诺字段。64位进程ticks由十进制字符串经CLI传递，避免JS数值舍入；不隐式重试。DevHost新增端点限只读契约/目录，不开放管理写入或PML执行；docs-only模式保留原限制。

### 6. 交接、准备页边界与退出码

安装完成页可以带 `--inspect-handoff`。它只调用 `setup.handoff.inspect`，不授予写入、启动或执行。没有该参数时，交接只把工具包根填进草稿。

准备工作区的 launch 与 verify 阶段只导航到既有启动页和会话页。它们不调用 `launch.plan` / `launch.execute` / `launch.observe`，也不调用 `connection.sessions` / `connection.select` / `connection.status` / `connection.test`。这些操作仍由对应页面在显式授权后调用。

Inno apply 失败的进程退出码是 10，分类名 `INSTALL_APPLY_FAILED`。管理器处理器失败的退出码是 7，稳定原因在 `error.Code`。管理器配置冲突也使用 10，但是另一个进程。对照表是 `InstallExitTaxonomy`，代码和测试引用它，不另写一份数字表。未知结果不自动重试。

docs-only交付的证据链接SHALL通过实际HTTP验收，不能只证明目标文件存在。已发布的`.cs`源码证据明确按`text/plain; charset=utf-8`提供并保留原始字节与`nosniff`；只增加这一明确映射，未知扩展保持404，开发路由保持404、写请求403。源码临时宿主通过不代称已安装宿主通过；修复包与具体升级计划需独立核对和批准。
