# 从任务地图进入契约与实现

PMLTWIN围绕一条主路径组织入口：**了解当前情况 → 选择要做的任务 → 定位当前步骤 → 查看结果与下一步**。项目目录、内部Script、方法和证据提供深入了解的分支，不要求先读完资料才找到任务。地图中的选中位置是阅读位置，不能据此判断业务已执行或验证通过。

## 总体：从项目主干选目标

打开[本机项目入口](http://127.0.0.1:19439/)，先选任务分支，再进入Feature。分组方便阅读，没有暗含执行顺序。完整Feature、Script和原始规范仍保留；没有登记流程的功能会说明缺少步骤，不从目录顺序编造流程。

Web只读。Desktop Dashboard依据当前会话情况提供下一入口：启动工程、查看连接原因、选择操作目标或选择任务。可用Host的绿灯与明确选定的操作目标是两件事；检测到E3D不会自动查询、部署或执行PML。

## 分支：Feature步骤与内部Script

启动、Ribbon和迁移使用元数据已有流程。进入某一步时保留原flowId、stepId及关联Script；同一个Script在不同步骤出现时仍能识别当前位置。前后步骤及已登记的未知/恢复分支说明可去哪里，阅读下一步不会实际执行它。

围绕当前任务切换内容分支：

- **任务地图**：目标、当前步骤、交付与下一入口。
- **完整契约**：Feature职责/输入/输出/副作用/恢复；Script输入、前置、方法、副作用、校验、回执、失败恢复七项原文。
- **实现方法**：同修订Roslyn精确符号、源码和静态调用关系，及可用的DocFX成员说明。
- **证据与来源**：验证时间、产品版本、范围、排除项及原始规范来源。
- **完整目录**：全部Feature、Script及原规范索引入口。

从细节返回任务地图会保留原步骤。旧实体和section链接继续定位对应分支。摘要/详情控制内容披露，外观控制主题；它们不改变任务位置、实际业务状态或证据结论。

Desktop明确选择并核验会话后，从任务入口进入对象读取、Form/Gadget、数组读取或注册函数。导航不自动提交查询或赋予权限。unknown结果继续核对原编号，不能当失败重新提交。

## 共用数据与边界

作者元数据经校验生成共享render model中的`taskMap`。Web与FigCraft使用同一组实体、步骤、交付和限制；元数据修改仍走原共同发布链，失败保留上个有效版本。FigCraft地图是可编辑静态参考板，不宣称具备Web导航或产品操作。

完整契约见[任务地图动线细约](../../openspec/changes/integrate-pmltwin-product-platform/features/task-map-navigation.md)。既有[方法预览](contract-method-preview.zh-CN.md)、[共同生成链](contract-generation-pipeline.zh-CN.md)及[Dashboard会话边界](dashboard-session-health.zh-CN.md)继续适用。

## 汇总：随路径深入，沿原路返回

先从项目地图找到目标，再从Feature步骤进入Script契约、方法或证据，最后返回原任务。完整资料仍可核对，但不会占据每个任务的主路径。原平台未完成业务与展示改造分别跟踪；地图和源码关系不代表全部产品已经完成。

Web验证包括完整首屏任务入口、步骤及前后路径、旧链接、删除步骤焦点、完整原文、真实五修订共同更新，以及最新Roslyn正文/文件SHA和精确DocFX成员链接。浅深Web与FigCraft图做过代理视觉复核，用户视觉认可与Figma真实宿主验收仍独立记录。详见[本轮验证记录](../validation/task-map-navigation-2026-11-01.json)。
