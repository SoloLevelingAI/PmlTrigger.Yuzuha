# Dashboard会话监测与摘要小标题 · 2026-11-01

## 总体契约

用户希望文档更容易阅读，并实际打开桌面：启动首先进入Dashboard，之后打开E3D能够自动更新灯态。默认Dashboard已存在；持续发现、Host新鲜核验和失联降灯尚未接通，原平台也仍有27项未完成，不能把文档/视觉完成称为产品全部完成。

本切片实现只读会话可用性闭环并实机验证，不执行PML、修改工程数据库、部署Host或自动切换工作目标。绿灯明确命名“Host可用/身份已核验”，不代表所有业务、许可或部署都通过。先定契约再实现。

## Feature契约

### 桌面入口与灯态

- 正常启动显示总览/Dashboard，不落到启动参数表单。保留现有视觉风格、启动/配置/Ribbon入口；主会话状态在首屏有清楚的标题、灯色和文字原因。
- 页面打开后立即开始独立只读监测，周期约3秒，single-flight、不阻塞UI；发现和核验有超时/取消，关闭窗口停止。刷新失败、过期或程序睡眠恢复不得保持旧绿。新鲜期上限10秒，展示观察时间。
- 灰色：未发现会话/尚未核验；黄色：发现进程但无Host、探测中、协议不足或未知；绿色：当前PID、进程启动时间、专用管道、非空Host模块及所需协议均由本轮只读状态回执核对；红色：已核验目标失联、身份不符或明确失败。颜色配文字，不仅依赖灯。
- 候选发现不等于连接成功。状态核验使用原aveva.sessions.list及aveva.session.status/select只读契约；每次有PID和启动身份，首次可读取Host宣告模块，此后同一身份钉定模块。模块改变清旧证据，不悄悄接受新模块。
- 多个会话可以逐项显示可用性，但不静默切换当前操作目标。自动监测与SessionWorkbench的显式目标分开；可用绿灯不自动授权查询/执行。用户选择目标后，原每次操作前复核仍有效。
- 监测与正在进行的用户操作不抢模型锁、不重发PML、不改查询输入。后台新快照不得覆盖新代次；候选消失/PID重用/管道或模块变化/超时/超龄立即失去当前绿。恢复后可用性可重新变绿，工作目标仍遵循显式选择规则。

### 旧工作目标失效修复

SessionWorkbench重新核验因IOException/Timeout/取消等抛出时，必须清Status及旧查询/对象/数组结果，不能绕过ValidateIdentity留下TargetVerified=true。保留输入和错误原因，不把发送后未知结果改成成功，不自动重放。明确选择失败也不保留上一个目标。

### 文档摘要小标题

不再让契约ID、参数字符串、语言/角色和警告作为连续无标题段落。两视图按清楚的中性小标题组织：任务目标、所属任务交付、输入/职责摘要、实现方式/实现范围、适用边界、详细细约。Feature实现scope与Script语言/职责分别说明，不混成状态保证。

新增稳定页内key overview:goal/deliverables、contract:input-summary/implementation-summary/boundaries/details；原七字段contract:field:<原ID>和披露key不变。字段内容、来源、规范状态与exclusions完整保留，旧URL继续可用。小标题使用字号/字重及适量间距，不再添加一层彩色大框。Web/FigCraft同源事实及原生可编辑参考板保持对应。

## 验收与汇总

1. 有意义单测覆盖无会话、发现无Host、绿色严格身份/协议、失联、异常/超时、超龄、PID重用、模块/管道变化、旧代次和single-flight，真实/合成证据分别标注。
2. SessionWorkbench已有查询后StatusAsync抛异常不再假绿；保留未知执行语义及输入。
3. 实际打开桌面并确认Dashboard首页；无会话时记录非绿，随后通过已有授权启动APS /ALL DESIGN，观察自动发现和真实Host核验变绿。无真实Host只能报黄色，不以夹具代验。
4. 断开/消失与恢复优先用隔离探测/进程夹具验证，不强关用户E3D；如由本任务创建的会话确需关闭，须核对PID/start及未被用户使用，不盲目杀进程。
5. 文档所有摘要组有小标题、TOC层级/旧锚点、双视图/移动/展开保持可用；实际查看WPF与Web/FigCraft渲染，不把功能测试代替视觉复核。
6. 总分总交付：Dashboard说明当前可用性 → 选择Feature/会话 → Script细约及方法 → 真实证据与未完成范围。说明用户可试什么、尚未完成什么，不升级原27项业务状态。
