# Dashboard会话绿灯与本机试用

## 总体：这一条体验可以试，项目仍未全部完成

本次桌面构建默认打开“总览 / Dashboard”。界面后台持续只读发现工程进程，并核验Host身份。2026-11-01已使用本机现有APS、`/ALL`、DESIGN配置，从没有运行会话开始，通过真实桌面启动一次E3D 2.1；Dashboard自动显示“1个Host可用·身份已核验”。没有手动刷新，没有自动选择操作目标。

这证明本机E3D 2.1的会话可用性闭环，不能推广为所有产品、数据库、许可或业务功能全部通过。原平台仍有27项未完成任务，包括跨产品完整启动、活动数据库迁移、完整Ribbon/CAF以及整体验收。

## Feature：看懂灯，再选择操作目标

| 灯态 | 含义 | 可以做什么 |
|---|---|---|
| 灰 | 没有会话，或尚无核验 | 打开已有工程，等待发现 |
| 黄 | 发现进程，但Host/协议尚未就绪或证据未知 | 看原因，等待初始化或检查对应Host |
| 绿 | 新鲜只读回执核对PID、启动时间、管道、模块和V1协议 | 选择操作目标后进入相应工具 |
| 红/过期 | 原连接失效、身份变化或核验失败 | 看原因，重新明确选择/核验；不沿用旧结果 |

监测约3秒一轮，界面显示观察时间，新鲜期不超过10秒。打开或关闭工程、Host失联、模块改变后不会永久沿用旧绿。只读监测不执行PML、不部署文件、不修改工程数据库，也不替用户切换多个会话之间的操作目标。

“工程会话可用性”和“操作目标”是两件事。绿灯后若要查询，点击“选择操作目标”，在工程会话页明确选择并核验目标。已有Form/Gadget、数组和对象的有界查询仍按每次操作核验，函数执行继续需要原来的明确许可；可用绿灯不是执行授权。

当前E3D已由本次验证打开，不需再按“启动工程”重复创建。后续自行试用可使用仓内`artifacts/desktop-dashboard/start-desktop.cmd`，它绑定同目录独立通信CLI；不是安装包更新，也不修改系统入口。

## 内部Script与文档细约

| 单元 | 方法与边界 |
|---|---|
| DashboardSessionMonitor | 独立候选及只读探测；single-flight、超时/取消、10秒新鲜度、身份钉定及旧代次拒绝 |
| DashboardSessionProbe | 原生CLI的list/select/status只读契约；每次提供PID及启动身份，核验模块/专用管道/协议 |
| MainWindow.Dashboard | UI线程呈现新鲜快照、候选原因和时间；默认Dashboard，关闭停止，smoke禁真实探测 |
| SessionWorkbench | 核验异常立即撤销旧状态/查询；epoch门禁阻止等待中的旧回执重新填回，不重发未知操作 |
| 文档摘要 | 中性小标题区分目标/交付、输入/职责摘要、实现方式/范围、适用边界与详细细约；七字段及旧URL保持 |

文档小标题不增加另一套事实。目标/交付仍标明所属Feature，语言/职责不是警告；完整Script七字段及逐字段来源不变。Web与FigCraft参考板都保留“任务目标”和“适用边界”等可扫描层次，不以更多彩色框代替说明。

## 汇总与验证范围

本轮有38项会话/监测测试，覆盖身份不符、无Host、超时、失联、过期、PID重用、模块/管道变化、single-flight、取消和等待中旧结果回填。WPF合成回归包含12页、两主题、三视口及118张图，绑定错误为0；它验证界面，不替代实机。

实机证据来自实际桌面截图、单次启动后的发现及严格PID/64位启动时间/DESIGN管道回执。真实断线/恢复没有通过强制关闭用户工程来验证；相关边界由隔离注入测试覆盖。E3D和桌面保留供用户查看。
