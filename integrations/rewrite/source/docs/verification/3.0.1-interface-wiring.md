# 3.0.1 界面恢复与 C# 接口接入验证

日期：2026-10-19。分支：`rewrite/archon`。用户澄清本轮要核对“架构里的 C# 接口与功能接入”。

## 对上一版完成度的修正

3.0.0 已有用例、平台适配器、组合根和核心行为测试，但用通用表单重做了界面。类型存在检查、项目编译及截图中按钮可见，不能证明页面功能完整接通，也不能证明视觉符合原稿。原导入与迁移结果核验缺入口，分享不能选子集、不能单独导出工具，工具库与设置混在一起，部分状态及草稿会串到下一条目。

3.0.1 保留这些用例及分层，将原 `LaunchDesk.App/App.xaml` 的资源和 `ToolSettingsView.xaml` 的布局接到新页面模型，恢复设计的侧栏、卡片、紫色启动区、蓝色工具区、输入框、下拉框、图标及窗口边缘。没有把旧 MainViewModel 或旧业务服务引入 Desktop。

设计输入仍为 `docs/design/LaunchDesk-fusion-v2.figcraft`；LikeC4 原稿及历史 Archon 审阅状态没有改写。

## 页面 → 端口 → 实现

所有生产装配集中在 `rewrite/LaunchDesk.Bootstrap/DesktopCompositionRoot.cs`。页面只引用 Contracts。具体每个方法的目标类型和调用次数由运行时 `GetInterfaceMap` 与 DispatchProxy 记录，见下方 JSON；诊断不记录参数、返回值、密码或配置内容。

| 页面 / 操作 | 端口与主要方法 | 生产实现 / 下游 |
| --- | --- | --- |
| 登录：新增、保存、复制、删除、核验保存 | `ICatalogService`：Read / SaveProfile / Copy / Delete / InspectCommit | `WorkspaceCatalogService` → `IWorkspaceStore` / `JsonWorkspaceStore`；保存新密码调用 `ISecretVault` / `WindowsSecretVault` |
| 应用：登记入口、查找候选、保留人工路径 | `ICatalogService.SaveDefinitionAsync` / `RefreshDiscoveryAsync`；`IEntryDiscovery.FindAsync` | `WorkspaceCatalogService` / `WindowsEntryDiscovery` |
| 许可：登记、检测、就绪检查、订阅 | `IResourceMonitor`：Refresh / RequireFresh / Watch；`IResourceProbe.ObserveAsync` | `ResourceSupervisor` / `ConnectionHealthPolicy` / `WindowsResourceProbe` |
| 启动：提交、阶段、原编号查询、停止观察 | `IOperationCommands`；`ITaskQueries`；`IOperationHandlerRegistry`；`IOperationHandler`；`IOperationContext`；`IRunJournal` | `OperationCoordinator` / `OperationProjectionService` / `OperationExecutionContext` / `JsonRunJournal` / `LaunchOperationHandler` |
| 子进程环境、凭据与实际观察 | `IProcessGateway`：CaptureEnvironment / Start / Observe；`ISecretVault.ResolveAsync` | `WindowsProcessGateway` / `WindowsSecretVault`。窗口出现不会标为项目登录成功 |
| 工具：新增、编辑、移除、配置变量 | `ICatalogService.SaveDefinitionAsync` | `WorkspaceCatalogService`。工具库与设置分别呈现，切换工具清除旧选择及预览 |
| 刷新来源、选择最新、来源预检 | `IToolSourceCatalog`；`IPackageReader` | `ToolSourceCatalog` / `PackageReader`。刷新保留人工选择；ZIP、7z、文件夹、普通文件映射均有入口 |
| 部署预览、确认交付、保护目录及互斥 | `IDeploymentPlanningService`；`IStagingStore`；`IFileDeliveryPort`；`ITargetLeaseProvider`；`IControlDataGuard` | `DeploymentPlanner` / `PrivateStagingStore` / `FileDeliveryPort` / `CanonicalTargetLeaseProvider` / `WindowsControlDataGuard` / `DeliveryOperationHandler` |
| 记录、恢复与回滚 | `IDeploymentHistoryQueries.ReadAsync`；`IDeploymentPlanningService.PreviewRecoveryAsync`；`IFileDeliveryPort.ReadReceiptAsync` | `DeploymentHistoryQueries` / `DeploymentPlanner` / `FileDeliveryPort`。操作要先产生新预览再确认 |
| 变量改名、预览、明确应用 | `IVariablePlanningService.PreviewAsync`；`IEnvironmentStore.ReadAsync` / `ApplyVerifiedAsync` | `VariablePlanner` / `WindowsEnvironmentStore` / `VariableOperationHandler`。Process 变量随子进程注入；持久变量另行确认 |
| 选择性分享、独立工具导出、导入及原编号核验 | `IConfigurationShareService`：Export / PreviewImport / Commit / InspectCommit；`IConfigurationDocuments`：ReadShare / WriteShare | `ConfigurationShareService` / `ConfigurationDocuments`。ShareSelection 补充 ToolIds，不导出凭据 |
| 迁移：明确来源、预览、副本、校验、启用、原编号核验 | `IMigrationPlanningService`；`IMigrationStore` 全部方法；新增 `IMigrationQueries.InspectAsync` | `MigrationPlanningService` / `JsonMigrationStore` / `WorkspaceMigrationService` / `MigrationQueries` |
| 数据位置及目录入口 | `IWorkspaceLocationResolver` | `WorkspaceLocationResolver`。侧栏及设置都使用同一端口 |
| 管理员交付 / 变量写入 | `IPrivilegeBroker.ExecuteAsync` | `WindowsPrivilegeBroker` / `LaunchDesk.Worker`。只在明确选择管理员执行时使用 |

`IMigrationStore.ReadSourceAsync` 现在显式接收来源路径，消除适配器内“上一次选择”的可变状态。迁移只向空工作空间启用，当前版本文件需要完整目录而非重新迁移。历史审阅 JSON 不回写；增补决策写在 `rewrite/architecture.json`。

## 实际验证范围

原生 WPF 的 `ButtonAutomationPeer` 调用真实 ICommand，再等待端口调用和结果断言；不是仅执行 Click 路由事件，也不以按钮名称或接口类名存在作为通过依据。

- 40 项按钮操作通过，包括普通文件的子目录映射、真实部署及回滚、变量预览、独立工具导出、确认导入、迁移副本启用与原编号查询。
- 30 种接口在组合根有绑定；71 个不同方法留下调用记录。另按实现类型独立计数，四个操作处理器分别验证。
- 测试采用真实 JSON 配置、提交历史、运行日志、包读取、暂存、文件交付、回滚与迁移。凭据、许可探针、进程和环境变量使用内存替身；管理员调用禁用。另构造默认生产组合根，核对其绑定为 Windows 适配器，不启动外部观察。
- 27 项核心回归通过，包含原生进程参数及环境、真实 Worker 协议、互斥、写入中断恢复、提交不确定结果、健康身份与去抖等。
- 10 页 × 3 个尺寸 × 3 个渲染密度，90 张 PNG；绑定错误为零。尺寸为 1440×1000、1180×800、1120×740；密度为 96/144/192。基础登录表单不要求向下滚动，固定主按钮不位于 ScrollViewer 内。
- 补充检查迟到的探针和运行阶段不能覆盖较新的 UI 状态；任务投影完整等待 Dispatcher 内的异步工作。

以下三种方法在本轮原生 UI 夹具中明确不调用，不伪装成已验证：

| 方法 | 范围 |
| --- | --- |
| `IPrivilegeBroker.ExecuteAsync` | 已接到明确的管理员执行路径；UI 夹具禁用提升。独立 Worker 核心测试验证鉴权和原计划写入；真实 UAC 交互待联测 |
| `ISecretVault.DeleteAsync` | 已有实现，保留给另行核验的无引用凭据清理。当前保守保留凭据，不把删除配置等同于删除秘密 |
| `IWorkspaceLocationResolver.OpenDirectoryAsync` | 已接侧栏和设置。UI 夹具避免弹出资源管理器，目录打开失败仍以 Result 显示 |

真实 AVEVA 项目登录、许可签出、VMware 断网与主机重启未在本轮测试中执行。渲染密度测试也不等于真实多屏 DPI 切换。多机执行、远程凭据和插件运行时仍是预留边界。

## 复验与证据

```powershell
$env:MSBuildEnableWorkloadResolver='false'
dotnet build rewrite/LaunchDesk.Rewrite.slnx -c Release --no-restore -m:1 -nr:false -p:UseSharedCompilation=false
& rewrite/LaunchDesk.Rewrite.Tests/bin/Release/net10.0-windows/LaunchDesk.Rewrite.Tests.exe artifacts/frontend-repair/core
# 每次使用新的证据目录；等待原生 EXE 退出后读取报告。
& artifacts/win-x64-rewrite-3.0.1/LaunchDesk.Archon.exe --contract-smoke artifacts/frontend-repair/published-contracts
node scripts/check-contract-wiring.mjs artifacts/frontend-repair/published-contracts/report.json
& artifacts/win-x64-rewrite-3.0.1/LaunchDesk.Archon.exe --ui-smoke artifacts/frontend-repair/published-ui
node scripts/check-rewrite.mjs
```

当前证据位置：

- `artifacts/frontend-repair/published-contracts/report.json`：按钮、端口、逐实现调用、默认生产装配和夹具范围。
- `artifacts/frontend-repair/published-contracts/wiring-matrix.json`：每个方法的实现与验证分类。
- `artifacts/frontend-repair/published-ui/report.json`、`bindings.log` 及 90 张 PNG。
- `artifacts/frontend-repair/core/results.json`：27 项核心验证。
- `artifacts/win-x64-rewrite-3.0.1/manifest.json`：发布文件哈希。

发布保持独立目录，未替换 2.0.4 安装、桌面入口、真实配置、许可服务或虚拟机。要迁移真实配置，应在该独立版中先预览并确认旧文件。
