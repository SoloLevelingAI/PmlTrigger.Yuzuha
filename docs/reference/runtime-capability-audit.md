`pmlforms.pmlfrm` 的编程思路可以复用：声明 Form/Gadget → 初始化 → 绑定 callback → 生成数组 → 写入 LIST 的 dtext/rtext → 按选择取对应数据。自有 `tests/ai-pml/development-probe/YuzuhaDevProbeForm.pmlfrm` 已有这种用法。这里的 LIST 是列表式展示，不应称为已经完成了带单元格编辑、排序筛选的通用数据网格。若“建立一个表”指数据库表，本轮没有实现该能力；Form 数据列表与 AVEVA 模型数据库是不同对象。

PML FUNCTION、OBJECT、FORM 可以用代码开发。REHASH 更新检索索引，Object/Form 重载后仍要核对新实例/窗体的实际行为；函数被既有会话使用后的替换也应单独验证，不能把 REHASH 回执当作函数已换版的证据。HTML 文件由本地 Web 宿主提供，网页更新不依靠 PML REHASH。当前路线不依赖 PMLCMD。

### 无响应的定位边界

Walker 的 `ReadNode` 使用 `.attribute()` 读取属性，失败后对 DBREF 尝试 VAR SPLIT；该段代码没有显式执行按钮 callback。属性求值可能进入原生代码，尚不能排除间接事件或原生阻塞。当前记录仅能证明：宏执行回执成功，后续结果读取请求断管，进程仍有线程忙碌。尚未采集调用栈，无法把根因归给 Attribute 事件、Walker 或心跳。

恢复后的定位顺序：保存每段开始/结束与耗时 → 只取结果数量 → 取首行和少量行 → 分批读取 → 完整读取。每次核对会话及原始结果，失败不重放。分页只能限制已生成结果的传输量，不能保证属性 getter 或 VAR SPLIT 本身不会阻塞。

## 目录统计替代笼统健康度

本批 `DirectoryInspector` 增加同名重复候选、PML 专属字节数、按类型和文件夹统计；桌面概览去掉未定义的健康度圆环，展示具体数量。CLI/MCP 的目录检查复用同一结构化结果。

| 指标 | 口径 |
| --- | --- |
| 全部文件/字节 | 已扫描目录中的普通文件数及文件长度之和 |
| PML 文件/字节 | .pmlfnc、.pmlobj、.pmlfrm、.pmlmac、.pmlcmd；不计 pml.index、备份及日志 |
| 重复组数 | 单次扫描根目录内，文件名和扩展名忽略大小写相同、路径不同的候选组数 |
| 多出条目 | 各组文件数减一之和；不表示可以删除或内容完全一致 |
| 类型/目录 | 各类型的文件数/字节；各文件所在目录直属文件的数量/字节，避免子目录重复加总 |
| 部分扫描 | 达到预算、链接、访问失败时数量仅为下限，零重复不代表完全没有重复 |

这些字节是源码文件磁盘占用，不是运行内存或单个方法内存。当前不读正文，不统计方法声明数量，不做内容哈希去重，也不推断多个 PMLLIB 根目录之间的加载覆盖关系。桌面最多显示 20 个目录、20 组候选及每组 10 个路径；完整已扫描结果通过目录检查 JSON 返回。扫描只读，不清理文件。

## 更新、用户目录与 CI/CD

现有安装器按发布清单列出覆盖内容，并保留覆盖备份；知识库 SQLite 不进入发布包，也不会在升级时自动重建。普通启动配置和 WebApps 数据默认位于 LocalAppData 下的独立目录。CI 使用仓库 checkout 和指定产物目录，并不主动收集用户电脑的数据。

但不能承诺“任意位置的用户数据都绝不会被覆盖或打包”：若用户改的是发布清单内同一路径文件，安装计划会将其列为更新；备份不等于合并保留。当前打包脚本会复制源码树的 PMLLIB/PMLUI/runtime/skill/docs，若人工把用户 JSON 或业务源码混入这些目录，现有 SQLite 后缀检查并不能识别所有用户数据。推荐通过固定交付清单和干净构建区进一步保证边界。

当前路径设置也未统一：

| 数据 | 当前入口 |
| --- | --- |
| 工作台设置、活动与部署备份 | `YUZUHA_STATE_DIR` 或 LocalAppData/YuzuhaToolkit；特定开发根配置另有回退 |
| 知识库 | GUI 可选目录并保存；服务使用 `YUZUHA_KNOWLEDGE_DIR` 或安装根 knowledge；GUI 设置尚未统一传给服务 |
| HTML 应用目录、绑定和调用记录 | WebApps 的 `--data-dir`，默认 LocalAppData/YuzuhaToolkit/WebApps；桌面启动器尚未提供统一路径设置 |
| 函数登记、信任记录 | 各有状态文件/环境变量，部分默认仍在安装根 |

采纳的后续约定（待实现）：设置中提供“用户工作目录”，首次推荐 Windows Documents/YuzuhaWorkspace，可修改。用户源码放 Projects，自有部署文件放独立 UserPmlLib，知识资料/索引放 Knowledge，应用绑定放 Apps，导出放 Exports。缓存、凭据引用和内部状态保留在 LocalAppData/YuzuhaToolkit。已有路径优先，不因升级自动搬家；迁移要有文件清单、空间检查、备份、散列核对和失败回退。UserPmlLib 只有实际加入目标会话 PMLLIB 后才算注册，不把默认路径当作已生效。

更新只能覆盖程序归属的文件；用户源码、经验、索引、自有应用和绑定应单独存储并保留。新增路径如果与程序交付目录重叠，应明确提示或拒绝。CI 验收应放置用户哨兵文件，覆盖升级和回退场景，确认内容与散列保持不变；当前不能用“离线测试通过”替代这组迁移验收。

## 知识库可视化与增删查改

当前桌面已有搜索结果表、完整正文、来源路径、数据库/chunk 定位和本窗口检索历史。后端工具支持注册并索引用户指定资料源、显式重建、分层搜索、追加本地经验。当前 GUI 明确提示“尚未接入索引构建和经验写入”；没有完整的编辑、删除、恢复管理。

待实现的管理方式：左侧按内置/项目/官方/自有/经验分类，右侧显示内容、来源、版本、更新时间、体积和检索状态。用户新增资料源；修改自有原文后增量更新索引；删除资料源默认只解除登记，删除索引与删除原文分开；经验支持纠正版本、软删除与恢复。内置说明随程序发布，官方原文保持来源完整性，个人批注独立保存。修改检索切片不能代替修改原始资料。所有写操作要显示实际目标目录，避免 GUI 和 CLI 写入不同知识库。

## CLI、注册契约与宽松调用策略

CLI 已能独立启动同一个程序的临时 MCP 子进程并调用工具，用户无需先把 Yuzuha 注册到 Codex/DSH 的 MCP 设置。AI 客户端只需具备本机命令执行能力并知道 CLI 用法。MCP 注册仍可用于原生工具发现与持续连接，是可选入口；CLI 内部复用 MCP 协议不代表需要用户管理客户端注册。多步调用使用同一 batch 保持会话，单次 CLI 退出会释放选择状态。

当前有两套不同语义：原生命令入口可以执行已授权的任意 PML；函数登记入口只解析有限的明文 pmlfnc 标量签名，记录源码哈希，登记后默认不允许调用，需授予该版本权限。信任清单只是提示。函数登记权限尚不约束原始命令和 HTML 自有绑定，因此当前不是“只允许注册函数”的统一执行边界。

可以让源码 XML 和加密文件旁的 XML 契约共同生成能力目录与 DocFX。建议元数据包含 ID、种类（Function/Object 方法/Form）、目标、参数/返回、适用版本、文件 SHA256、依赖、数据库/文件读写等声明副作用、是否可能交互、预期耗时与验证引用。明文扫描只能提取可确认事实；加密实现使用发布方提供的伴随 XML，记录“实现不可检查”，并把契约绑定到加密文件哈希。扫描后的自动登记不等于向 E3D 注册 PMLCMD，也不等于已加载。

DocFX 负责展示共享的契约；程序需要单独的契约读取器和策略判断。目前没有把 DocFX、源码 XML 或伴随 XML 自动转为运行时登记的实现。

拟议设置两种模式：

1. 日常开发宽松模式：允许用户选择的开发范围内已登记能力，未知风险可按用户设定放行并记录；不逐条弹窗。保留目标身份、版本变化提示、执行记录及失败不重试。
2. 仅登记模式：CLI、MCP、HTML、桌面所有入口执行相同策略；原始命令不能绕开登记，或需用户另行开启开发入口。可按用户/组织策略允许数据库修改、文件输出、外部程序等影响范围。

风险显示应分别保留“作者声明”“扫描发现/不可检查”“本机许可”“实测结果”。代码或 XML 自称 safe/readOnly 不足以授予权限；签名能确认来源，也不能证明执行无副作用。`attribute()`、动态拼接、宏和回调可能越过静态分析边界，未知必须保留。用户可以预先选择宽泛策略，程序按该策略判断，无需每次重复确认。该模式尚未实现，本批不改变现有调用权限。
