# Spec Delta

## Purpose

让用户对明确选择的 AM/E3D 会话执行有证据的连接检查，并在界面和管理器 CLI 得到一致状态。区分未测试、已发现、测试中、可连接、失败和失效，防止文件登记、进程存在或历史结果被误认为本次通信成功。

状态：候选，未 sync/archive。connection.test、可过期证据模型及桌面通信目标绑定已实施；无会话、身份变化、管道/协议问题、部署变化和过期状态已有合成 Host 验证。新总览/连接 Feature 与真实 AM/E3D 绿灯仍未验收，不把模拟通过显示为真实连接。当前定位见 [design.md](../../design.md#现有源码与测试定位)，范围见 [实施验证](../../implementation-verification.md)。

## ADDED Requirements

### Requirement: 每个产品与会话可显式测试连接

管理器 SHALL 提供 AM/E3D 测试按钮和对应 CLI 操作。存在多个会话时 MUST 要求选择明确目标；检查 SHALL 通过通信 CLI 完成身份与协议握手，不执行用户 PML、建模或写库操作。

#### Scenario: 没有运行会话
- **WHEN** 安装已发现但没有正在运行的 AM/E3D 目标
- **THEN** 显示未连接及启动入口，不显示红色的已验证故障或绿色连接成功

#### Scenario: 同时运行两个工程
- **WHEN** 发现两个候选工程会话
- **THEN** 先显示产品、工程、模块和 PID 供选择，不自动选择任意会话

### Requirement: 绿灯必须对应本次完整核验

连接状态 SHALL 以进程身份、启动时间、PID 专用管道、Host 模块和协议能力的同次结果为依据。只有全部满足当前能力要求时才亮绿灯；配置登记、TCP 可达、进程创建或曾经成功 MUST NOT 单独触发绿灯。

#### Scenario: 进程存在但 Host 不可用
- **WHEN** 工程窗口存在但专用管道缺失或握手失败
- **THEN** 显示失败阶段与修复入口，不把发现状态升级为已连接

#### Scenario: 旧 Host 协议能力不足
- **WHEN** 已连接 Host 缺少请求所需协议版本
- **THEN** 显示协议不兼容及缺失能力，不标为该能力可用

### Requirement: 连接证据失效必须清除旧成功状态

状态 SHALL 关联产品安装、部署修订、PID、启动时间、模块与测试时间。目标退出、模块改变、部署更新或证据超过有效期时 MUST 降为失效或待复测，并保留历史记录；超时不自动重发操作。

#### Scenario: PID 被新进程重用
- **WHEN** 原目标退出且相同 PID 对应新的启动时间
- **THEN** 清除当前绿灯，下一次操作重新发现和核验目标
