# 用户工作目录与知识库管理

本功能对应 TRACE28、TRACE29、TRACE32。设置提供推荐默认路径与显式迁移，桌面知识库提供个人笔记增删查改、修订历史及资料索引管理。源码、命令签名和 AVEVA 调用协议保持兼容；本轮没有更新已安装客户端。

## 推荐位置与数据边界

在“设置 → 用户工作目录”选择位置，推荐 Windows 文档目录下的 `YuzuhaWorkspace`。文档目录可能受 OneDrive 或组织策略重定向，以界面显示的实际路径为准。

| 子目录 | 用途与本轮接入范围 |
| --- | --- |
| Projects | 建议保存用户源码；迁移时复制已有内容，不自动搬入外部工程 |
| UserPmlLib | 自有部署文件；保留已有内容，不自动改 AVEVA 的 PMLLIB/EVAR |
| Knowledge | 知识索引、个人笔记、经验、资料库回收站和重建备份；GUI与新启动的原生CLI共用 |
| Apps | HTML 应用分类、按钮绑定和服务端运行资料；新启动 WebApps 共用 |
| Exports | 建议保存导出成果；浏览器下载仍由用户选择位置，不强改浏览器设置 |

内部设置、启动配置、凭据引用、活动日志和部署备份仍使用 `UserDataPaths.StateDirectory`，通常为 LocalAppData/YuzuhaToolkit，或现有 `YUZUHA_STATE_DIR` / 安装根回退。密码仍在 Windows 凭据库。函数登记、信任记录的现有路径和调用权限本轮不变；安装器保护这些内部目录。

首次打开不创建、不搬移资料。旧安装 knowledge 和旧 LocalAppData/WebApps 存在时继续沿用，直到用户明确切换。知识路径优先级：`YUZUHA_KNOWLEDGE_DIR` → 保存的独立知识目录 → 已配置用户根/Knowledge → 未配置统一根时已有旧 knowledge → 推荐根/Knowledge。应用路径优先级：显式 `--data-dir` → `YUZUHA_WEBAPPS_DIR` → 已配置根/Apps → 未配置根时已有旧 WebApps → 推荐根/Apps。`YUZUHA_USER_DIR` 覆盖保存的用户根。存在目录环境覆盖时，设置中的迁移拒绝执行并解释原因，避免保存一个实际不生效的路径。

## 切换目录

1. 输入新路径，点击“预览目录切换”。预览列出复制/核对的文件数和前 20 个路径映射；服务端冻结全部文件 SHA256 与设置指纹。文件上限 100000。
2. 等待使用旧数据的CLI调用结束，并关闭使用旧数据的HTML宿主，点击“复制核验并切换”，在确认框核对目标。新启动的CLI调用和宿主读取新设置；独立MCP服务已禁用。
3. 程序取得数据库写锁，以临时文件复制、校验后改名；同名同内容可复用，不同内容拒绝。源文件增删改、设置变化、SQLite WAL/SHM、链接/目录联接和重叠目录都会停止迁移。
4. 完成后才原子保存路径设置。旧目录保留；失败回退本次新增且未被其他程序修改的目标文件，原有目标不覆盖。可能保留空目录；磁盘或权限错误显示失败，不宣称迁移成功。

迁移以合作写锁、前后指纹和停用旧客户端为边界，不能阻止外部程序在切换后继续写旧目录。不会强杀服务。HTML 已运行实例的健康信息如果指向另一数据目录，桌面拒绝复用并提示关闭该实例；没有目录信息的旧宿主在启用统一目录后也会被拒绝。

## 知识库的日常操作

知识库首页可直接跳到“个人笔记”或“资料库与回收站”。已有搜索、完整正文和来源定位保留，默认同时检索本机补充资料。

- **新增/编辑**：新建笔记，填写标题、正文、来源/验证上下文，保存新修订。个人笔记存入 personal.sqlite3，同一事务保存版本并更新全文检索。可以把当前搜索结果复制成个人笔记再编辑。
- **查询/历史**：首页搜索可命中个人笔记；列表选中笔记后查看历史修订。历史不可原地覆盖，选取历史内容再保存会创建新修订。另一窗口已经修改时拒绝过期编辑，并保留当前输入。
- **移除/恢复**：移入回收站需要确认，默认取消。删除生成修订、撤出当前检索，历史仍在；勾选显示回收站，选择笔记后恢复。没有永久删除入口。
- **资料库**：填写名称、来源类型和本机 PMLLIB/PMLUI/WebHelp 路径建立索引。列表显示角色、条目数、文件字节与读取状态。修改原始资料后显式更新所选索引，会在同一写锁下先保存 SQLite 备份，再构建并校验新索引。
- **资料库回收站**：移除仅移动索引及来源清单，外部原文保留。恢复遇同名目标拒绝覆盖。内置指南只读；project、experience、personal 不允许按普通资料库重建/删除。经验仍使用既有追加接口，纠正可追加经验或另写个人笔记。

本轮是桌面可视化管理，不包含在浏览器编辑官方原文、源码编辑器、增量索引算法或 XML 自动执行登记。对资料源的“更新”指按原登记目录完整重建；若更换来源目录，可以新建另一个资料库并把旧索引移入回收站。

## 升级保护与 CI

更新仅交付程序文件。打包检查拒绝用户目录、数据标记、SQLite/DB 和活动侧文件；安装计划及执行前再次拒绝用户目录路径和标记目录。已存在的程序文件只有与上版发布清单的 SHA256 相同，或已经等于新版内容，才允许更新；用户修改或未归属的同名文件使整个预览停止，保留现场，要求先移到用户目录。不能把备份当成允许覆盖用户修改。

原有安装备份、冻结计划校验与失败恢复继续使用。CI 从干净 checkout 构建，不把真实用户目录加入发布输入。仅靠后缀无法判断任意业务 JSON 的含义，因此用户资料不应混入源码交付树。旧版安装器不受本次新保护约束。

更新本机前，先出具具体安装预览，并提醒关闭 AM、E3D、Yuzuha 工作台及相关宿主；确认关闭与批准后才更新。本轮测试使用临时文件和离线 UI，没有向无响应的 AVEVA 发请求，也没有重新验证 ELDATA。

API XML：`UserDataPaths`、`UserDataMigrationService`、`KnowledgeRepository.SaveNote/ListNotes/NoteHistory/RebuildLibrary/ArchiveLibrary/RestoreLibrary`。新管理逻辑复用原 KnowledgeRepository 检索与建库，不更改既有 MCP 工具签名。
