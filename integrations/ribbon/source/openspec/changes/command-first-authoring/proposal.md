# 功能命令优先的 Ribbon 使用方式

## Why

用户明确选择“先管理功能命令，再编排 Ribbon”。现有主要入口强调 Tab → Group → 按钮，迫使用户在内容尚未整理时先做布局决策。功能表格混合定义字段与引用字段，难以判断修改会影响一个位置还是所有位置。顶部编辑器 Ribbon 与待设计 Ribbon 还形成两套相似操作区域。

## What Changes

- 默认进入当前文档功能库，集中维护名称、Macro、图标和 Tooltip，显示引用数量与未放置状态。
- 将功能库、Ribbon 编排、检查与部署作为可自由往返的工作视图，不设强制完成向导。
- Ribbon 编排只修改引用的菜单页、分组、顺序与大小；从功能库放入所选分组，支持拖放和非拖放入口。
- 全局命令区收紧为文件、编辑、视图、帮助及撤销重做；上下文操作靠近当前内容。
- 明确“移除引用”与“删除功能”，提供所有使用位置与影响范围。
- 任务动线作为验证场景，不要求用户先搭流程图才能编辑 UIC。

## Impact

第一阶段功能库限定当前 UIC，不建立跨文件共享功能数据库。复用现有 buttons 定义与 group.items 引用、文档会话、增量撤销、后端和部署预览。新增 FigCraft 草案保留旧六页设计；桌面实现、真实回放及自动视觉检测仍在待办中。
