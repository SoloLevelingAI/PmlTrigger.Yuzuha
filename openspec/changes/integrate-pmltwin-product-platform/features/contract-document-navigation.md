# 文档布局、页内目录与区块设计契约 · 2026-11-01

## 总体契约

将图谱整理为常规文档网页：左项目目录、中当前正文、右本页大小标题。选中Feature/Script后，当前契约先于同级卡片。保留原始元数据、三轴状态、摘要/详情、来源、方法和共享发布门禁。先细化契约再实现。

不同区块用语义标记色及浅底区分；正文和大小标题主要依靠字号、字重、行距，中性正文保持高对比。Web和FigCraft使用同源设计token与事实数据，生成CSS及原生参考布局，不各维护另一套颜色。

## Feature契约

### 页面和完整目录

顶部品牌/视图/外观紧凑排列，减少大幅标题和维护状态占用。面包屑、当前标题和披露控件与正文相邻；生成/版本细节按需展开。左侧始终可达概览、18个Feature及14个Script，使用语义列表/普通按钮，当前实体有文字和aria-current。共享Script按明确主入口列一次，其他关系仍在原契约。搜索覆盖项目范围，正文卡片分类不永久隐藏左目录。

≥1280为三栏；900–1279左目录+正文，本页目录收至正文前；<900为单栏，两种目录各用原生折叠入口。导航折叠不参加内容“全部展开/折叠”。宽度切换保证桌面目录可见；窄屏选择后关闭对应目录，Esc关闭并回summary，无遮罩和滚动锁。桌面两侧sticky并独立滚动，中间自然滚动、控制阅读行长。宽表/代码仅在自身容器滚动，页面不横向溢出。

### 本页标题、定位与状态

目录使用nav和有层次链接，包含主区块、选中契约5/7字段、原需求/来源、当前方法分组及附录分类。只扫描正文明确登记的目标，按实际阅读顺序穿开放Shadow DOM；排除全卡字段/数据表行/编辑器，不形成另一个巨型目录。

目标用稳定key/逻辑level，基于区域、原section ID、方法ID、附录ID，不按标题或位置造身份。显式定位沿parentElement/ShadowRoot.host查祖先details，写中央披露key后单次重绘，再按key定位新节点、避开顶栏并聚焦标题/summary；只开必要分支，保持全局summary。失效目标回正文标题并提示。

URL增加section，保留实体、view/detail/catalog/method/flow/q/status。显式定位可增加历史，刷新/前进后退恢复目标与必要展开。scrollspy只更新aria-current=location，不抢焦点、不筛选、不重绘正文。普通render不重开旧section；全部折叠将子锚点写回顶级父节，刷新仍保持折叠并高亮可见父节。

新revision保留有效section、披露、可恢复焦点与章节相对位置；删除目标清section并回正文标题，不能以旧像素跳到无关段落。import/draft/live的section状态隔离。重建时断开旧观察器、监听和RAF，旧代次回调不影响新节点。只解释已登记key，URL/标题不执行代码。

### 共用区块颜色和排版

角色固定overview、contract、flow、implementation、evidence、reference，各有中文标签及light/dark的accent/surface。分别用于概览、契约/目录、流程、方法、验证、规范/来源；色彩表示类别，不代表实现或验证成功。

tokens.json独立sections/typography结构生成`--atlas-section-<role>-accent/surface`及字号/字重变量，不混淆既有theme状态角色。区块边线、标记和浅底用角色色；标题/正文用theme.text，限制仍用warning。默认正文16px、卡片14px、辅助信息至少12px；标题以字号和字重区分。两套主题的正文在区块底上至少4.5:1，焦点和关键控件边界可见。

FigCraft由同源token生成颜色变量和排版，既有组件对应角色，新增静态文档布局参考板展示左目录、真实Script正文、右层级标题及六类样式。保留原始七项文字、状态/限制，板可编辑但不虚报目录交互。Figma适配可复用同源样式，真实宿主验收仍单列。原生失败继续lastgood。

## 作品集视觉完成度（用户补充，不以分色代替）

美观与作品集展示仍是独立验收维度。颜色token、无溢出、结构/测试通过只是前提，不足以把参考线框称为完成的作品集。视觉认可与业务实机验收分别记录，不推断用户已经认可。

- 构图：Web与FigCraft保持明确的主次，当前任务标题与价值是第一焦点；目录、维护信息和样式示例为辅助，不与正文争夺面积。作品集先说明所属任务/价值与可追溯交付，再引导阅读技术字段；不能只把所有元数据排成表格。
- 层级：标题/正文/辅助三层字号及字重一致，使用8px基础节奏，24/32px章节间距，12px圆角和克制分隔线；同类边距和左右基线对齐，不靠更多框线和大色块制造层级。
- 配色：内容类别使用少量浅底、细边或标记；正文与标题中性、警告有独立语义。六角色样例集中为紧凑图例或独立样式板，不能把六个大占位色框当作品集内容。
- 设计稿：原生文档参考板补品牌/面包屑/选中目录/当前任务层级、细约正文与页内标题的完整构图；原文字段是内容，不逐段重复套同样粗描边方框。参考板保持可编辑，不能用栅格截图伪造原生布局。
- 实际目检：保存浅/深Web桌面、移动及FigCraft实渲染图，逐项记录首屏焦点、信息层级、文字舒适度、对齐/留白、配色克制、事实可追溯。检视失败应回改实现；测试通过不自动写成视觉通过。记录代理视觉复核与用户视觉认可的不同状态。

## 验收与汇总

1. 1440/1024/390 × help/portfolio × summary/full共12组合：布局、目录可达、无页溢出；两侧sticky/滚动、手机选择/Esc/resize。
2. 当前launch-workflow首屏/七字段、闭合祖先定位、scrollspy、同名身份、键盘、刷新/返回真实验证。
3. 全局折叠不反向重开；revision章节/相对位置/焦点、删除回退、独立来源隔离；保留安全导入、方法及lastgood。
4. 六角色两主题的CSS与token、实际底色对比度一致；真实FigCraft板可编辑且同源原文/字号/颜色有可复验记录。
5. 总分总：目录找到Feature → 正文读契约/Script → 本页标题定位方法/规范 → 来源与证据核边界。阅读改造不勾原平台业务任务。
