本轮以`578c1e0c86133fc50c6288dba023ad72bf4cf117`为审查基线，修复文档CI、补启动/会话证据接线、增加契约专项CI，并收紧ION阅读布局。它不完成全部平台融合，不修改canonical需求状态，也没有重新启动或操作AVEVA。

## 从契约到实现，再到验收

运行`npm ci`后执行`npm run contracts:styles:serve`，打开本机19440端口的ION。手机先选择五类目标与任务；桌面从“工程发现与启动”或“会话发现与身份核验”进入工作区。

1. “摘要”分别说明规范、实现及验证范围。标题下的验证条目可直接进入证据栏目；它不是当前Host在线状态。
2. “完整契约”保留全部字段、关联需求和来源SHA。来源默认折叠，减少重复信息；展开仍可核对完整身份。
3. “实现方法”是显式绑定的静态源码，不代表运行轨迹。新电脑需要按[方法预览说明](contract-method-preview.zh-CN.md)显式捕获Roslyn/DocFX并完成共同发布；缺少产物时明确显示不可用。
4. “验证证据”分别显示日期、offline/UI/runtime、结果、环境和未涵盖内容。展开每条记录的“来源与身份”，点击“查看完整验收报告”，打开已核对SHA的原文。

报告接口只接受已批准的evidence source ID及SHA，不接受调用方文件路径。账本或报告变化、摘要过期、文件越界、格式/大小不符时拒绝返回；原文以带sandbox的`text/plain`显示，不执行报告中的HTML。完整报告为本机内部阅读，机器信息不会被复制到公共元数据。

## 持续验证与失败定位

`.github/workflows/development.yml`增加独立`contract-workbench`任务，与原文档/WPF任务并行。它运行：

```powershell
npm run contracts:check
npm run contracts:styles:themes
npm run contracts:test
npm run contracts:browsers:install
npm run contracts:ci:browser
```

生成检查覆盖元数据、共享token与六主题；专项覆盖来源/证据归属、只读修改边界、发布恢复、方法身份与桥接、SHA报告读取及拒绝反例。浏览器入口自启临时loopback服务，检查真实公共内容、隔离方法组件和紧凑布局。每项子进程最多180秒；失败非零退出并保留日志/截图。CI使用锁定Playwright的Chromium，本机可显式设置`CONTRACT_ATLAS_BROWSER_CHANNEL=msedge`。

没有FigCraft时原生专项明确跳过，没有本机Roslyn捕获时精确绑定专项明确跳过；这些记录不伪装成真实原生/源码验收。浏览器方法组件使用隔离夹具，不调用Host，也不替代真实生产者验收。CI产物名包含精确提交SHA；浏览器回执记录提交、dirty、浏览器、时间和每项退出码。

原CI的39项注释缺失已补充中文XML说明，未降低门槛。完整文档构建仍要求源码注释、测试目的登记、Roslyn、DocFX及链接检查通过；WPF继续独立验证，不因契约页通过而省略。

继续执行流水线时另补齐34项既有C#测试目的，并修正共享事件处理器被多个真实控件引用时的溯源假设：逐控件保留页面/来源身份，每项仍必须匹配精确程序集、完整签名及resolved状态。遗漏的Ribbon报告与本说明已纳入明确的DocFX资源清单，没有关闭链接警告。
