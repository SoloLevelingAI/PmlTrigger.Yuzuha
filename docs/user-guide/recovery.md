# 核对回执与恢复

出现错误时，先保留原操作 ID、退出码、JSON 回执和相关备份位置，再判断下一步。不要在收不到回包时默认原操作没有发生。

| 回执或实际状态 | 处理方式 |
| --- | --- |
| 明确拒绝，且未执行 | 按原因修正输入或范围，重新生成并审阅计划 |
| 明确成功 | 回读实际文件、环境或验证结果，确认任务断言 |
| 超时、断线、`mayHaveExecuted=true` 或 unknown | 按原编号读取事实并核对实际目标，不自动重发 |
| 部分写入或部分恢复 | 保留完整回执和备份，逐项确认已完成与未完成范围 |
| 目标在操作后又被外部修改 | 保留冲突，先人工比较，不覆盖后续修改 |

部署与 EVARS 恢复使用本次回执中的恢复引用，并要求明确恢复授权。启动使用原 `operationId` 观察；取消等待不表示已撤销启动。

恢复配置历史会产生新的修订，不会启动 AVEVA，也不会恢复已删除的密码。应用升级、运行环境恢复和工程模型更改分别处理。

求助时提供脱敏后的操作 ID、目标身份、错误码、回执与实际观察。不要把凭据或未脱敏工程资料放进公开报告。
