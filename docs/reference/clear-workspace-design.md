# Clear Workspace 界面设计与落地约定

对应 TRACE34；状态为 **设计评审**。用户明确选择“先交付 FigCraft 设计与可操作预览”。[设计源与图片](../../artifacts/docfx/navigation/repository/docs/design/clear-workspace-r1/README.md)和[交互预览](../../artifacts/docfx/navigation/repository/docs/design/clear-workspace-r1/prototype.html)独立于正式界面；生产调用保持原有行为。

## 按用户任务组织入口

| 主入口 | 收纳内容 | 常用操作 |
| --- | --- | --- |
| 工作台 | 工程启动、最近配置、当前会话摘要 | 项目、用户名、密码、MDB、模块；路径和参数渐进展开 |
| 应用 | HTML、原生 Form、PML Function/Object 绑定、部署检查 | 分类查找 → 核对目标与参数 → 执行 → 结果表格 |
| 知识库 | 个人笔记、官方参考、资料源、归档 | 搜索 → 阅读 → 编辑 → 修订历史/恢复 |
| 运行记录 | 启动、部署、工具调用及失败回执 | 按操作追踪状态与下一步，不用笼统健康分数 |
| 底部设置 | 用户目录、外观、启动行为、凭据、集成配置 | 低频操作集中；清除密码必须二次确认 |

原来的会话、开发、部署、审查、测试、能力登记等页面不会因导航收拢被删除。落地时映射到相关二级页面并保留旧路由，先核对访问频率和可发现性。本轮原型只覆盖最常见的任务，不宣称完成全部旧页面替换。

## 视觉与窗口

日常浅色；白色阅读区、灰绿导航、深绿主要动作。桌面基准 1440×960，DocFX 1440×1024。字号 32/21/15/13，辅助信息最低 11；对齐优先，边框和间距区分信息层级。浏览器窄屏保留分类、设置和搜索入口，表格分页避免无限延伸。

自绘窗口采用统一标题栏视觉。生产 WPF 集成建议以现有窗口配合 WindowChrome 实施，不能只设置无边框而丢掉系统行为。验收需覆盖拖动、双击最大化、8 向缩放、系统菜单、Alt+Space、Windows Snap、任务栏、多显示器、DPI 100/150/200%、高对比、键盘焦点和可访问名称。网页的最小化/最大化/关闭只作用于预览面板，不是原生 Windows 行为验收。

## DocFX 与原生 UI 的职责

DocFX 顶层改为开始使用、开发指南、API 参考、更新记录；首页按连接/开发/排查组织。文章采用左目录、中正文、右页内导航；API 类型和方法保留源码/XML 自动生成，搜索结果应标注指南/API/运行记录来源。无需改变 PML 或 C# 签名来迁就导航。

原生 PML Form 适合简单输入、按钮与已有 AVEVA 交互；表格、筛选、导出仍可在 HTML 中完成。统一管理器负责登记、参数和路由。预览没有改变现有 IPC 或引入 PMLCMD，也未决定必须嵌入 WebView。

## 动效与可访问性

悬停/按下 120 ms，页面淡入 180 ms、最多位移 6 px，侧面板设计建议 240 ms。生产运行中的等待反馈由真实状态驱动，不能用固定动画制造成功。原型的数组读取明确标为合成演示。

支持 `prefers-reduced-motion` 与设置中的减少动态效果；保留焦点轮廓、语义按钮、表单标签及状态播报。当前 MCP 工具和本机 Programs 目录未找到 EffectCraft，没有调用或伪造其格式。已用 FigCraft 原生过渡和 CSS 展示动效意图；取得 EffectCraft 后可按同一时长与状态约定替换。

## 接口与数据边界

统一用户目录和知识库功能已经实现，说明见[用户目录与知识库管理](user-data-and-knowledge.md)。此设计的业务操作仍需逐项映射到现有服务，不能把原型内存状态当生产存储。后续实施以现有回执、权限和错误处理为准；当前 ELDATA 大数组无响应问题仍待单独复验。
