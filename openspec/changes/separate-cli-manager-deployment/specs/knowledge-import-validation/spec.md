# Spec Delta

## Purpose

使用户从管理器 GUI/CLI 导入自己选择的 PMLLIB、PMLUI、WebHelp 或已有知识数据库，并在启用前获得分层检查报告。完整性、格式兼容、检索可用、来源可定位和内容新鲜度分别记录，防止把相关检索结果或可打开的 SQLite 文件当作已验证资料。

状态：候选，未 sync/archive。资料源/已有库双路导入、只读检查、原子发布、来源内容指纹与库身份检索已有后端离线验证；用户选定的 E3D 2.1 和 AM 12.1.SP4 资料已分别在工作区验证库导入，默认用户目录与安装程序未切换。新知识 Feature 的 GUI 分层报告及同库 GUI/CLI 对照仍待验收，不把后端闭环称为 GUI 已交付。当前源码见 [设计定位](../../design.md#现有源码与测试定位)，实际/合成范围见 [实施验证](../../implementation-verification.md)。

## ADDED Requirements

### Requirement: 两类导入在启用前提供计划

管理器 SHALL 分别支持用户选定资料源建立索引，以及已有数据库导入。计划 MUST 展示来源、产品版本、目标目录、角色、冲突和预计操作；只读取或检查不得自动建库、重建或替换现有库。

#### Scenario: 导入官方资料目录
- **WHEN** 用户选择本机某产品版本的 PMLLIB/PMLUI/WebHelp
- **THEN** 只对该选择生成建立索引计划，执行后按来源与版本登记，不扫描其他未选目录

#### Scenario: 同名数据库已有不同内容
- **WHEN** 已有数据库的导入目标存在不同内容
- **THEN** 默认拒绝覆盖，允许重新命名或返回重新选择，不以导入为由重建原库

### Requirement: 数据库检查区分完整性兼容性与检索可用性

检查 SHALL 分别报告 SQLite 完整性、必要表与 schema 版本、行数与关系、FTS 可查询及索引一致性、来源清单、检索抽样和错误。损坏或不支持版本的数据库 MUST NOT 启用；结构有效但来源缺失可按降级状态保留检索。

#### Scenario: SQLite 可打开但索引或格式不兼容
- **WHEN** 数据库完整性正常但 schema 不受支持或 FTS 检索失败
- **THEN** 显示具体失败项并保持未启用，不用单一“完整性正常”替代整体结果

#### Scenario: 数据库有活动写入
- **WHEN** 发现活动写锁、WAL/SHM 或不能取得一致快照
- **THEN** 不进行裸文件复制，要求停用写入或采用受支持的一致性备份后重新计划

### Requirement: 来源映射与新鲜度具有可核验语义

系统 SHALL 保留原始来源和用户选择的本机映射，按来源版本显示缺失或变化状态。仅文件数和总字节相同 MUST NOT 作为内容未变化的强证明；结果须携带数据库身份与片段 ID，过期或缺源状态不得被搜索相关性掩盖。

#### Scenario: 同长度源文件被修改
- **WHEN** 源文件内容改变但文件数及总字节不变
- **THEN** 基于内容指纹的检查发现变化，或明确标为仅粗略比较而非已验证新鲜

#### Scenario: 导入来自另一台机器的库
- **WHEN** 原始来源目录在本机不存在
- **THEN** 标为来源缺失，允许用户预览并登记本机映射，不改写历史来源记录

### Requirement: 个人资料与程序升级独立

程序升级 SHALL 保留用户知识库、个人笔记、经验、修订和信任记录；普通资料库管理不得重建或删除保留库。导入流程 MUST 先在暂存区校验，通过后才发布登记，失败不改变既有启用状态。

#### Scenario: 更新程序文件
- **WHEN** 管理器更新自身或 Yuzuha 运行载荷
- **THEN** 不自动导入、更新、重建或分发用户和官方资料库
