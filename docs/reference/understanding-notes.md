# 理解与排查笔记

笔记帮助回答具体问题、保留有用发现并缩短下一次排查时间。先选问题，再选表达方法；5W2H、康奈尔笔记等都是可选工具，不预设其中某个最好，也不要求每页填一套模板。

[迭代与意见记录](iteration-log.md) · [后端调用链示例](backend-tracing.md)

## 按问题选择表达方法

| 要解决的问题 | 可用方法 | 应留下的信息 |
| --- | --- | --- |
| 不清楚功能解决什么、适用哪里 | 简短背景说明；信息较多时选 5W2H | 目的、使用者、触发条件、环境、范围、约束；成本或数量没有资料时不编造 |
| 不清楚数据怎样计算或转换 | 输入与处理与输出表、公式、逐步算例 | 输入类型与单位、转换规则、分支条件、输出、不变量和边界值 |
| 不清楚一次请求如何跨进程处理 | 分层调用链、时序说明 | 调用者与被调用者、路由、线程、状态、失败传播；静态关系与运行记录分开 |
| 出现症状，需要缩小问题范围 | 决策表、检查清单、故障树 | 观察到的事实、区分原因的检查、预期观察和下一步；原因猜测标为假设 |
| 需要复习或保留经验 | 问题与笔记与结论；也可采用康奈尔笔记 | 提示问题、关键发现、来源和一句结论，避免复制整页源码 |
| 需要解释为何选择一种实现 | 简短决策记录 | 背景、选项、决定、理由、代价、何时重新考虑；不因记录决定创建新审批流程 |
| 需要证明某条判断成立 | 主张与证据对照、反例或边界案例 | 主张范围、测试 ID、输入断言、提交和环境；未运行、历史结果和当前运行分开 |

简单问题可以只写一个带来源的短段落。复杂问题可以组合两种方法，例如先用输入输出表理解计算，再用决策表排查失败。图、表和模板不承担证据本身的作用。

## 一条有用笔记的最小内容

1. **问题与结论**：读者要做什么决定，目前能得出什么结论。
2. **依据**：对应源码、测试 ID、回执或日志；有运行结果时附提交、时间、环境和证据位置。
3. **适用边界与下一步**：哪些条件会改变结论，还有哪个检查能减少不确定性。

与特定实现相关的笔记放在功能说明旁；跨功能的决定进入[迭代记录](iteration-log.md)；一次运行的原始输出留在本机 artifacts。继续使用 Git、DocFX 和现有测试目录管理，不建立另一套存储和状态系统。

源码解释要能区分三种内容：代码直接可确认的事实、从事实推导的结论、尚需验证的假设。对后端步骤还应说明是否写文件、改状态、执行 PML 或跨进程，以及失败能否重试。

问题解决后补上根因、起作用的检查、修正及验证结果。被排除的原因只在有助于避免下次误判时保留，并注明排除依据。后续源码或环境变化使结论失效时更新适用范围，保留替代记录；模型名称或填表数量不作为笔记质量指标。

## 示例 空页为什么仍能继续查询

**问题与结论**：Gadget 清单一页没有条目，是否表示已读完？不能只看条目数；需要检查 `NextIndex`。扫描预算针对原生槽位，普通成员、未设置引用或稀疏槽位可以消耗整页预算。

| 观察 | 检查 | 能得出的结论与下一步 |
| --- | --- | --- |
| `Items=[]` 且 `NextIndex>0` | 核对 `Scanned`、预算和原请求 | 仍有后续扫描位置；保持查询条件和预算，使用 `NextIndex` 续读 |
| `Items=[]` 且 `NextIndex=0` | 核对请求种类、目标和回执成功状态 | 本次枚举到末端；不能据此证明其他会话或加载状态也为空 |
| `IndexUpperBound` 大于返回项数 | 核对是否存在稀疏或非 Gadget 槽位 | MAXINDEX 是索引上界，不能当作有效项总数 |
| 请求失败或没有有效回执 | 查看错误代码、原始错误、目标身份和 RequestId | 不能归类为“成功的空页”；先定位失败层，不自动重试已发出的执行操作 |

实现与逐步算例见[Form 查询的后端计算](backend-tracing.md)。关联案例：[稀疏槽位与续读](../../artifacts/docfx/navigation/tests/test-ca2d98e78c56bc11.md)、[未设置的 Gadget](../../artifacts/docfx/navigation/tests/test-4904333c619aea26.md)。关联表示这些断言可供复刻，不表示本页已经附有当前运行通过凭证。
