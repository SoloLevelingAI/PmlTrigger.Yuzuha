# 布局状态

FigCraft 修订 design/figcraft/workspace-layout-restore-0.9.figcraft 保留 0.8 画板，先增加停靠预览和恢复状态，再实现 WPF。

前端以 SchemaVersion=1 的 workspace-layout.json 单独保存布局，位置为当前用户 LocalAppData/RibbonStudio/Desktop。保存主窗正常边界及最大化标记，工具种类、顺序、浮动标记和浮动边界；保留停靠工具的上次浮动尺寸。只恢复仍打开的辅助工具，不恢复已关闭标签，不恢复待确认写入计划。

移动/缩放防抖保存，停靠状态变化触发保存，正常退出在释放浮动窗前立即保存。使用同目录临时文件及 Windows MoveFileEx 原子替换，错误在状态栏反馈。启动期间暂停保存，完成恢复再开放保存；避免中途把已保存浮动状态改成停靠。

启动先恢复文档，再按白名单重建工具与控制器，应用主窗和辅助窗几何；已存在实例复用。显示器工作区通过系统 Screen 信息换算为当前 WPF DIP，选择与保存边界交叠最大的工作区，无交叠时回主屏，并收紧过大边界。未知或损坏配置保留副本后回退。不同 DPI/显示器组合仍需真实硬件矩阵验收，不能以当前 DPI 结果代替。

停靠预览使用主窗口 Adorner，包含目标页签与内容范围以及松手提示，不额外创建可见窗，不接收命中。Windows 移动消息更新预览，缩放/移出/取消时清除，松手才重设宿主。浮动窗在目标上方轻微透明以露出预览，离开后恢复。实际 XML 写入期间不允许停靠操作。

跨进程测试分三个独立 WPF 进程：保存浮动与停靠工具、恢复并再次停靠、第二次重启确认停靠。另验证越界、负坐标、非法几何与预览清理；测试配置只在隔离目录。

验证证据：.runtime/desktop-smoke-gE5Rvo/。原生既有工作流通过，seed/restore/docked 三次独立进程全部通过。使用屏外、负坐标、非法几何断言，预览不命中且清理后恢复浮动窗外观；断言停靠状态确实写入磁盘，而非只检查内存。

最终预览证据：.runtime/layout-restart-CwXnDe/restore.preview.png，三个独立进程均通过；0.9 已启动。默认启动仍只恢复真实已有布局，不注入示例浮动窗。
