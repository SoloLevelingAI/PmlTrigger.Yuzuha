# 开发与加载 PML

先[核验目标会话](connection.md)，再向 AI 说明要改的功能、允许修改的文件和验证方式。将开发过程分成可审阅的小步。

1. 读取内置用法和当前源码，确认产品与版本适用性。
2. 在开发目录编辑文件，核对差异及文件摘要。
3. 审阅部署计划，检查目标、备份和恢复位置，再明确部署。
4. 按文件类型完成 REHASH、Object/Form 重载或明确的加载命令。
5. 运行本次验证宏或调用，回读返回值、日志和断言结果。

调用前用 `op describe` 读取实际操作输入。配置写入、创建进程、执行 PML 分别需要对应授权；仅给一项授权不会自动扩大到其他动作。

数组表达式使用 `pml.array.read`，表达式不附输出赋值；完整命令或宏使用 `pml.command.execute`。不要为绕过加载错误而悄悄换成另一份实现。

保留部署、加载和验证各自的回执。加载成功只说明当前加载步骤完成，仍需按任务核对实际返回结果。超时、断线或结果未知时，按[回执与恢复](recovery.md)先调查，不自动重放执行命令。

需要查看具体实现和测试时，手工打开同版本[开发参考](developer-reference.md)。
