# 评审 测试与 HTML 应用的实现边界

评审迁移、桌面测试执行和 HTML 应用管理是已提出的功能方向。当前 WPF 保留设计页面，相关操作尚未接入。功能目录的“计划功能”表示实现状态，不能根据页面存在或目录登记判为已交付。

## AI 草稿评审与迁移

AI 的试验 PML 放在独立 `tests/ai-pml/<任务名>/`，不直接覆盖原生 PMLLIB/PMLUI。一次实质变更记录目的、差异、契约影响和实际验证。由一名人工审核对应源码版本和证据，批准后迁移。现有复制、哈希和备份能力继续复用，新增的是批准快照、目标文件、迁移回执和恢复记录。

审核通过、登记、允许调用、文件复制、PML 重加载、已加载版本核验与实机验证分别记录。改变源码或契约后重新评估旧审核是否适用。此页和目录元数据不授予调用许可，也不执行迁移。

## 桌面测试执行中心

复用 `scripts/run-documented-test.ps1` 和 `test-map.json`，按真实 ID 核验源码后执行。GUI 需要展示提交、环境、执行数量、结果和证据路径；失败、跳过、零匹配、未执行、历史结果及未知结果分别呈现。GUI 操作尚未接入，当前通过 DocFX 详情复制命令执行。

## HTML 应用管理

C# 负责登记应用来源、目录、版本、入口、启停状态、授权和记录。打开页面与允许 RPC 调用是不同操作。后续桥接复用既有业务服务、身份核验与权限，先定义来源和生命周期，再实现真实调用。开发 DevHost 的预览接口不代表已经交付 HTML 应用运行桥。
