# 从作品集摘要读到完整契约与实现

## 总体：先理解项目，再核对事实

PMLTwin将工程发现与启动、文件部署、Ribbon配置以及PML开发辅助组织为同一组任务契约。图谱展示三条独立信息：规范要求、当前实现范围、已有验证证据。目录完整不等于功能全部完成，静态调用关系也不等于真实执行记录。

作品集首页先呈现项目目标、目录数量和三条已登记任务入口；“契约与实现”提供逐层核对路径。两种视图使用同一份公开元数据和共享组件模型，可读取相同完整原文。外观、阅读视图、摘要/详情是三个独立选择。

页面上方的“全部折叠 / 全部展开”控制内容区域及嵌套组件，也作用于之后打开的契约和新共同修订。默认摘要；任意卡片仍能单独展开，状态栏提示局部调整。全局动作会清除局部覆盖，URL的`detail=summary|full`可以保存全局程度。

## Feature：一张卡片回答一项责任

总体目录可切换18个Feature、14个内部Script或全部32项。搜索跨两个类别；当前范围与结果数量明确显示，清空筛选恢复目录。

每张卡片先显示标题、职责摘要、实现状态、字段数量及已知边界。“展开完整契约”在卡内查看原文，“进入此契约”打开独立详情，两者各有用途。选中Feature后查看五项细约、关联原需求及原状态、所属Script、来源摘要和验证记录。项目总体保留自身字段，不再由当前流程中的少数Feature代替。

流程步骤的标题、连接和不确定/恢复分支始终可读，较长说明按步骤展开。未登记的流程、缺失的验证和证据排除范围直接写明。

## Script与方法：需要时继续下钻

Script详情完整保留输入、前置条件、方法、副作用、校验、回执、恢复七项字段。卡内和独立详情分别维护稳定key，避免展开一张卡时意外打开另一处详情。

全部32项Feature/Script都有明确方法映射范围：当前18项精确绑定、8项未纳入当前分析或快照不可用、6项非C#等不适用。映射只引用真实分析图中的完整符号，不按名称猜实现。当前有界目录包含347个方法及1,364条静态关系，未纳入目录的边保留边界说明。

本机共同生成页的“查看实现方法”可以进入签名、XML说明、声明位置、源码快照和直接调用位置。签名、静态分析限制、过期/未知状态持续显示，长说明与正文分组折叠；“全部展开”只打开已选方法，不自动遍历全部方法或触发编译。精确DocFX成员链接继续使用本修订中经过验证的资源。离线文件、草稿和独立导入不继承内部方法正文。

## 规范附录：原始内容仍可逐项核对

“完整规范与来源附录”包含10节、352行，覆盖原有G/B/T/S、界面、转换、模型及191条源码限定映射，保留原始ID、状态、元组和嵌套字段。可搜索附录全文并按分类筛选；窄屏在表内横向滚动，页面本身不横向溢出。这里的数量表示目录内容，不能当作测试覆盖率。

元数据生成共享IR的`referenceIndex`和`coverage`，Web与FigCraft沿用同一事实投影。新增Web折叠交互不改变证据ledger，不把纸面画板描述为自动获得交互。内部C#正文仍不进入公开SVG和原生文件。

## 汇总与验证

阅读顺序是：项目目标与任务 → Feature责任 → Script七项细约 → 实现方法与原始规范 → 证据范围。先用摘要选择关注点，再展开所需原文；全局按钮用于一次切换阅读程度。

局部展开在导航、筛选、主题、视图和共同修订更新后保留；实体移除时清理失效状态。导入与草稿使用独立状态空间。原生summary支持键盘操作，关闭包含焦点的正文会回到summary，实时更新恢复可定位控件的焦点和滚动。

复现阅读验收：

```powershell
node tests/contract-atlas-reading-browser.mjs
node tests/contract-atlas-disclosure-components.mjs
node tests/contract-atlas-reference-browser.mjs
node scripts/serve-contract-atlas.mjs --watch --edit --port 19439
# 另一个终端，核对当前真实服务与DocFX/原生产物：
node tests/contract-atlas-reading-live-browser.mjs
```

阅读专项使用真实Chromium；测试中的合成方法消费者数据明确标注，真实Roslyn、DocFX与共同生成服务另行核验。汇总证据位于`docs/validation/contract-reading-2026-11-01.json`。
