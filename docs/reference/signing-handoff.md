# 在另一台电脑完成代码签名

本机交付为未签名测试安装包，签名在用户指定的另一台电脑进行。本轮没有申请、复制或读取私钥/PFX，没有上传代码或安装包到签名服务。

## 只签安装 EXE

先核对未签名包与本批 SHA256。复制安装包到签名电脑，使用该电脑已经配置的证书或硬件密钥完成 Authenticode 签名与时间戳，然后验证。SignTool 支持 SHA256 摘要和 `/pa` Authenticode 验证；命令及证书选择方式以 [Microsoft SignTool 文档](https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool)为准。

这只证明外层安装器签名，不等于内部 EXE/DLL 全部签名。签名后安装 EXE 字节改变，必须重算 `installer.sha256`、Agent 包中的同一 EXE、`BUNDLE-SHA256SUMS.txt` 和外层 ZIP/发布散列。目标电脑仍需生成自己的安装计划，不能复用本机绝对路径计划。

## 完整签名发布

若要求桌面、MCP、知识库、Host、SetupBridge 与卸载器都有完整的签名链，需在签名电脑安排完整发布流水线：

1. 固定仓库提交与构建依赖，先完成所有编译。`installer/build.py` 会重编 SetupBridge，不能先签这个辅助 EXE 又让构建覆盖它。
2. 对自有 EXE/DLL 完成签名和验签。保留第三方原有签名及许可，不替第三方冒签发布者。
3. 更新 Native AOT 清单与整个 payload 清单，使它们对应已签名的最终二进制。
4. 再编译 Inno 安装器。卸载器签名需单独配置 Inno 签名流程；当前构建脚本没有这项自动化。
5. 签署最终安装 EXE，验证签名与时间戳，重新生成所有 Agent/ZIP/散列文件。
6. 在目标电脑重新生成安装预览，验证升级保留数据，再安装与启动验证。

当前脚本尚未提供以上完整签名流水线；这里是交接顺序和验收边界。不要修改已冻结计划或散列来绕过校验。证书选择、时间戳服务和签名策略由签名电脑的维护者确定。
