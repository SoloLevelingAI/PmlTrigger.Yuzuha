# Phayton R2 正式版

Phayton 0.3.4 将 R2 设计接入原生 WPF 工作台和 DocFX。工作台默认进入启动工程，沿用现有启动、凭据、部署、知识库和会话服务。图标栏选择工作领域，第二栏选择当前任务；窄窗口改用分组下拉框，全部入口仍可到达。

## 启动工程

左栏选择已保存的工程，也可打开全部配置，按名称、项目或路径搜索、收藏、复制和删除。DESIGN、PARAGON、DRAW 卡片直接设置已有模块字段；其他模块及 MDB 可手动输入。选择 AM/E3D 产品后继续沿用原来的入口发现、LaunchDesk 草稿和启动环境策略。

密码留空沿用已关联的 Windows 凭据。清除密码位于 **设置 → 登录凭据**，选择配置后再次确认。名称、安装路径、许可与特殊启动动作保留在高级区域；切换页面或主题不保存、不清除正在编辑的草稿。

## 知识库

| 分组 | 可执行操作 |
| --- | --- |
| 检索资料 | 搜索内置指南和本机资料，查看正文、来源和验证信息，复制为个人笔记 |
| 个人笔记 | 列表与编辑区并排；新建、保存新修订、读取历史、移入回收站和恢复 |
| 资料源与回收站 | 登记 PMLLIB/PMLUI/WebHelp，建立或重建索引，移除和恢复资料库 |
| 目录与检索记录 | 查看/修改已有知识目录，查看本窗口最近检索记录 |

这些页面使用现有知识仓库，编辑的是本机真实资料。只读官方原文保持原样。目录改变时，旧列表选中项不能直接写入另一个仓库；索引重建和删除仍需要已有确认。

## 设置与用户数据

设置分为用户目录、环境与路径、外观、登录凭据、AI 客户端和关于。用户目录仍推荐 `Documents/YuzuhaWorkspace`，允许显式修改；先预览、复制核验再切换，旧目录保留。名称变化不会自动迁移目录。

日常默认浅色，已有深色偏好保留。原生 WindowChrome 提供标题栏拖动、双击、窗口大小调整和最小化/最大化/关闭；窗口内容没有被整体替换为网页。AI 客户端自动写入管理、评审中心和测试中心中尚未接入的操作仍明确显示状态。

## DocFX

首页提供连接与启动、开发工具和理解结果三条阅读路径。真实全文搜索、Script 目录、C# API、PML XML 注释、源码与测试溯源继续由原有文档构建生成。`Ctrl+K` 定位搜索，文章保持左侧目录与右侧段落导航；阅读偏好保留原来的存储键，新增用户默认浅色。减少动态效果的系统偏好生效。

完整生成站点与自包含文档宿主随包交付。工作台侧栏 **开发文档** 打开本机随机端口的只读站点；核对站点首页散列后才打开浏览器。它不接受写请求，也不提供 AVEVA 操作入口，关闭工作台会结束本次创建的文档宿主。已有开发 HTTP 宿主未指定 `--docs-only true` 时保持原接口。

## 名称与兼容约定

展示名称、标题、图标与新版安装包统一为 **Phayton**。为使原有调用和数据继续工作，以下标识保持：

- `PmlTrigger.Yuzuha` 安装目录、Inno AppId、注册表安装定位键和管理标记。
- `YuzuhaToolkit.*` 程序及程序集名称、CLI 参数、MCP 工具、IPC 协议、PML 方法与环境变量。
- 工作区 JSON、用户目录、Windows 凭据键、知识库数据库和现有显示偏好键。

新开始菜单入口放在 Phayton 分组；已有 Yuzuha 快捷方式继续兼容，不删除用户已有入口。它们不代表两份安装。历史文档、来源名称、路径和真实 API 标识保留原名。

## 更新与验证

安装器保留用户数据保护、同名修改冲突拒绝、预览散列校验及备份恢复机制。发布载荷不包含用户数据库、应用配置、知识资料或本机 `pml.index`。本次更新不会迁移目录、重建知识库、改写 MCP/Skill 接入或运行 PML。

先审阅具体更新预览，再关闭 AM、E3D 和工作台并确认，才执行本机更新。关闭应用后仍需检查使用安装目录的后台宿主。签名交给指定电脑，本机包标注未签名。

[本批验证记录](../../artifacts/docfx/navigation/repository/docs/validation/2026-10-23-phayton-r2-production.md)区分源码测试、隔离桌面测试、真实文档浏览、打包、更新预览和本机安装状态。历史 ELDATA 无响应仍属于独立待验问题，本次界面测试不能关闭该项。
