开发维护索引

同一份模型与后端，两个交付包；本机开关只控制VM测试脚手架。 本页八节说明当前实现。VM没有启动，普通远程不依赖实验包。完整模型方案见八节功能说明。主题仍待视觉评审。

① 产品包与开发工具包

产品包包含原WPF界面与登录Feature；开发包包含模型CLI、LabControl与LabVix。两个包复用同一个WorkspaceHost和Domain/Application/Platform/Bootstrap程序集，打包时比较四个DLL的SHA256，拒绝分歧。没有再实现一套Monitor启动。VMware/VIX不随产品包加载或交付。

② 从界面顺着调用链找实现

产品入口：CompositionRoot → WorkspaceHost → LaunchWorkspace → LoginLaunchCoordinator → StartMonitor → WindowsProcessHost。原XAML、控件、布局和样式均未改。

③ 同一Model如何双向编辑

LaunchViewModel只转发字段到LaunchModel，不再保留一份业务字段。模型的中性Changed事件使后端补丁也能刷新绑定，不依赖WPF通知接口。前端只保留候选/证据呈现、忙碌状态和错误显示。

LaunchWorkspace负责候选合并、保存、扫描记录、后端执行；业务校验集中在LaunchModelRules与LaunchValidation。每次模型字段变更自动保存draft.json。Generation冲突通过文件租约与原子写入拒绝覆盖；外部文件变更后需重新打开载入，尚无文件监视/自动合并。

④ 执行时怎样冻结并保存

sequenceDiagram
  actor User as 编辑者
  participant Model as 同一Model
  participant Work as LaunchWorkspace
  participant Back as 共用后端
  User->>Model: 修改字段（草稿自动保存）
  User->>Work: 点击执行
  Work->>Model: Freeze，生成AttemptId
  Work->>Work: 检查草稿版本并保存完整快照与Record
  alt 写入失败或版本冲突
    Work-->>User: 失败阶段＋原因＋类型/错误码；不执行
  else 快照持久化完成
    Work->>Back: 只提交冻结请求
    Back->>Back: 校验／许可／凭据／具体脚本
    Back-->>User: AttemptId关联的结果与Record
  end

快照保存在数据目录snapshots/.json；端口原始字符串也保留，非法输入不会默默变成0。口令不进模型、快照或Log，仅保存本机凭据引用；敏感环境字段拒绝落盘。执行中继续编辑只影响下次；“保存配置”保留为命名配置操作，执行草稿不再要求另点一次保存。

⑤ 普通执行的失败返回

源码入口 成功与失败契约
LaunchModel / LaunchModelRules 非法端口保留原字符串，转换时报告字段错误；无前端业务准入
LaunchWorkspace.FlushDraftAsync 正常发布新Generation；外部版本冲突、文件/权限错误停止覆盖
LaunchWorkspace.ExecuteAsync 快照/Record/草稿冲突失败返回Rejected与具体阶段、原因、异常类型/HResult；不调用启动器
LoginLaunchCoordinator.ExecuteSnapshotAsync 共用原协调器/脚本；校验失败Rejected、无密码Cancelled；进程状态按既有契约返回
进程已创建或创建不确定 NeedsVerification，不能标为“未执行”或自动重试；结果仍按AttemptId归档

原始输入、执行快照和List/NLog分工不同，不维护第二份业务规则。窗口或Monitor退出码也不能当作实际许可签出证明。

⑥ VM与许可怎么调，默认为什么不开启

许可服务器、端口、RULES及本机服务检查位于共用LaunchModel；VM路径、允许根、预期UUID/MAC、VIX路径、凭据文件引用、超时和证据目录位于LabSettings，示例为lab.example.json。不修改许可密钥、绑定或时间。

DevelopmentSwitch.IsEnabled缺文件、损坏、false或机器/用户不匹配均关闭，不检测VMware或加载VIX。开关不随配置导出；Debug和环境变量不自动启用。以下仅是说明，本轮未执行启用或VM动作：

LabControl status
LabControl fingerprint --model <lab.json>
LabControl enable --local
LabControl run --runtime <开发包目录> --model <lab.json> --confirm-target <核对的摘要> probe
LabControl disable --local
调用顺序／源码入口 失败返回
LabControl.Main：status → IsEnabled 输出enabled/disabled，均0；关闭不是命令失败
enable/disable → SetLocal 只更新开关，不启动/关闭VM、不取消在途动作；成功0，InvalidOperationException为78，其他异常2
run → RequireEnabled → 参数与runner路径 关闭先返回stderr/78；参数、文件与进程启动失败一般stderr/2；子进程退出码透传
LabVix.Main：再次RequireEnabled → Read/SaveSnapshot → VerifyTarget → VIX 异常stdout JSON stage/error＋1；目标身份/Host-only不符不连接VIX；成功通常0，底层guest-program非零映射2
LabVix.Wait / Result 超时表示结果未知，不自动重试；结果保存至Records和records.jsonl，记录失败提示人工核验；finally只释放资源，不承诺回滚或关机

⑦ Feature装配与分包边界

共用WorkspaceHost以FeatureId=login.launch提供装配和释放入口，产品窗口与开发CLI都使用它。开发VM入口在独立目录，不进入产品slnx、注册或发布；没有实验包，登录Feature照常装配。具体CAF接口适配尚未实现。

XML Addin驱动装配：features.json不再生成，运行时以Addins/*.addin.xml为准。没有有效声明，工厂不执行、功能不呈现；VM动作还要求独立本机授权。登录Addin随产品交付，保持原UI。

架构测试覆盖新模型不依赖WPF、前端不依赖脚本/配置业务服务、产品不含开发类型或VIX导入。打包入口从同一源码构建两包并核对共用DLL，不维护复制源码。此隔离防止误装配，不是安全沙箱。
