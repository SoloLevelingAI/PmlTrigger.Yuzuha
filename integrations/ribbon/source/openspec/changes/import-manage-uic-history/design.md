# Design

## Context

本机 Marine 的 DesignCustomization.xml 和 OutfittingCustomization.xml 均有 Name=Ytools、Path=C:\AVEVA\PMLLIB\Other\UIC\YtoolsAM.uic 的登记。旧的哈希文件部署方案不适合直接更新此既有条目。

## Goals / Non-Goals

**Goals:** 保留现有文件结构、明确所有权、保存恢复依据、保持后端独立。

**Non-Goals:** 不承诺任意高级 UIC 控件可编辑，不自动修改原生条目，不删除实际 UIC 文件，不执行 Macro，不将路径分类宣称为官方签名鉴定。

## Decisions

- 项目保留 origin 原始 XML 和 sourceId；生成后按节点合并可编辑部分。快捷键、属性、其他容器保留。可见非 Macro 工具或上下文 Tab 明确拒绝，隐藏容器对删除按钮的引用也会阻止破坏性导出。
- 持久层采用独立 WorkspaceStore，每文档包含元信息及不可覆盖的版本 JSON。写入版本后原子替换文档索引，同文档写入串行。data/uic-workspace 是正式数据，.runtime 只用于测试。
- 编辑防抖自动记录，允许无效草稿持久化，但生成和部署继续严格校验。恢复旧版本增加新版本，不重写历史。
- 托管身份以持久 binding 为准；旧版部署须有备份凭证和匹配的当前 UIC 摘要。安装内其他既有项保守保护；外部明确路径文件为自定义待接管。前后端均检查权限。
- 接管优先复用按源路径匹配的文档或原始摘要吻合的当前导入文档，保留当前草稿，同时保存接管时源文件字节。部署只使用后端绑定中的原路径，不相信 HTTP 传来的内部 managed 字段。
- 移除只撤销加载登记，保留 UIC；恢复登记使用原 Name/Path。写前保存快照并备份，摘要冲突拒绝执行。部署前后都保存记录，失败也记录。

## Risks / Trade-offs

- [原生来源无法仅凭清单完全证明] → 明示保守只读分类及原因；不自动授予权限。
- [外部文件被多个模块引用] → 更新以文件为单位，不选模块；收集已发现安装与已知绑定中的模块引用，扫描失败明确显示。文件只覆盖一次，XML 保持原字节。
- [草稿占用磁盘] → 每文档自动草稿仅保留最近 5 次，后续保存时清理旧草稿；手动保存及含操作证据的快照长期保留。序号独立于当前数量递增，手动保存同一内容也能从草稿升级为长期快照。
- [文件系统无法跨安装文件与工作区单次事务] → 写前持久快照、部署备份、写后记录及清晰错误；不声称跨进程全局事务。

用户修正：导入编辑后无需先接管，也不需要选择模块。后端根据持久文档的 sourcePath 更新原文件，预览收集 N 个 XML 引用，确认覆盖前保存原始备份与快照。成功后记录发现的关联；原生/系统项仍只读。新增关联单独选择模块、预览并确认，只修改该 XML，UIC 内容保持不变。模块表保留单项移除/恢复。
