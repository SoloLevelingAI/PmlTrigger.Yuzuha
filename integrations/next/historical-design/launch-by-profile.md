# 按登录配置启动应用：新项目设计方案

状态：待确认，未创建应用项目、未实施或派发 Agent。`LaunchDesk.Next` 为候选名称；本文件独立保存于设计工作区，不修改原项目或 rewrite。下面除明确标出的“原行为参照”外，均为新项目拟议设计，不代表已有能力。

八股是呈现形式：①BRD、②PRD、③FRD、④SRS、⑤前端 SDD/SDS、⑥后端 SDD/SDS、⑦项目与扩展设计、⑧验收和追踪。营销只需①首句，使用者从③进入，开发者先读④—⑥再查源码；熟手可按股直达。前后端指本机 WPF 交互与后台业务，不引入远程服务器。

[客户八股简介](customer-brief.md)只讲价值、操作和反馈；本稿保留工程解释。已批准的基础库和新增 ArchUnitNET、FigCraft 要求见[共用架构与界面规划](architecture-and-design.md)：共性由架构承载，单个 Feature 只描述自己的完整用户任务，不把架构复杂度转嫁给使用者。

语言与依赖约束已记入 [OpenSpec 变更草案](openspec/changes/csharp-discovery-and-evidence/proposal.md)：产品功能能用 C# 就用 C#，不再引入 PowerShell 发现脚本；代理工作过程中可用 PowerShell。新增其他实现语言或专用工具必须先评审，Inno Setup 属用户明确指定的工具方向，但当前并未授权新增安装工作。第三方库优先评估，采用前仍须用户确认。

## ① 为什么做：保存组合，减少重复准备（BRD）

**切换项目还要反复填写登录信息？保存好配置，下次选中即可启动。**

目标群体是切换应用版本、项目和许可连接的使用者，以及准备这些配置的管理员，两种职责可以由同一人承担。集中保存组合，降低重复填写和错误关联的机会；不承诺未经测量的效率提升比例。

新项目要让操作和维护都容易理解：使用者知道下一步点什么，开发者从文档就能知道输入、调用顺序、基础能力和失败处理。验收收益拟用同组项目切换任务比较耗时、错配和求助次数；基线及目标待确认。管理员是配置维护职责，不等于 Windows 管理员权限。

## ② 提供什么：范围与角色（PRD）

本轮先用这一项 Feature 验证新项目设计，不等于批准重建整个产品。允许参考或复用原 UI 资源和布局，后台代码可以全新实现；新项目不引用原 App/Core 或 rewrite 程序集，也不修改它们。

| 角色 | 新项目拟提供的能力 | 边界 |
| --- | --- | --- |
| 使用者 | 选择配置、核对字段、提供本机密码、启动并查看状态 | 窗口出现不代表项目登录或许可签出 |
| 兼任管理员的使用者 | 准备应用入口、许可连接、登录组合 | 不负责安装目标应用、创建项目或发放许可 |
| 开发维护者 | 从前端输入沿请求到后台协调器追踪行为 | 不通过 ViewModel 访问许可服务、进程或后台协调器 |
| 拓展者 | 先参照现有新项目实现，再替换参数策略或平台适配 | 不把接口存在当作已有动态插件系统 |

配置由应用记录、许可记录和登录记录组成：登录记录引用前两者，包含项目、用户、MDB、模块和凭据引用。保存密码在本机凭据存储，普通配置只保存引用。新项目使用独立数据目录；读取、迁移旧数据必须另有明确任务，不能直接改写原工作空间。

原行为参照包括现有按钮顺序、密码交互、许可隔离及启动状态含义；这属于需要验证的行为目标，不要求继承旧内部结构。工具部署、全局变量管理、远程执行及动态插件加载不纳入本 Feature；若启动配置关联工具，所需子进程环境必须通过配置读取能力提供，不能静默忽略。

## ③ 怎样使用：初始化、首次配置与日常操作（FRD）

以下使用原 UI 名称作为拟复用的交互约定，尚无新项目可操作版本。

**首次配置：** “应用与版本 → 手动添加 → 保存应用”准备程序、工作目录以及 Monitor 的产品标识/初始化文件；“许可监测 → 新增许可 → 保存设置”准备服务器、检测方式及所需端口；“登录配置 → 新增配置 → 保存配置”关联二者并填写项目、用户、MDB、模块和密码策略；最后“返回工作台”。缺少应用或许可记录时，提示先准备关联记录。

**日常启动：** “工作台 → 选中配置 → 核对字段 → 启动选中配置 → 按需输入密码 → 查看状态”，然后在目标应用内确认实际登录与许可签出。“保存并试启动”先保存、后启动，启动失败不撤销已经保存的配置。

**少填一次：先自动找，再人工改。** 首次配置可运行本机专用 C# 发现程序，按可配置目录和文件模式寻找应用，将程序路径和可预设字段生成候选并初始化 `LaunchInput`。项目、MDB、许可地址等无法可靠推断的字段由本机预设提供，未知则留空；所有预填值可修改，预设不是验证结论，保存前仍校验。多个结果供选择，重新扫描不覆盖已保存配置或当前人工编辑。

发现逻辑按产品分别写，例如 `E3dDiscovery.cs`、`MarineDiscovery.cs`，不追求相互复用；仅约定候选名称、程序路径、入口类型、预填字段、字段来源（发现/预设/人工修改）和诊断。增加产品就是新增 C# 实现并登记清单，不建设插件框架或通用规则引擎。

```text
自动查找（拟议）：
    读取启用的发现器、搜索根、深度/超时上限和字段预设
    调用清单中的 C# 发现器，各自查找对应产品
    保存扫描输入、候选与诊断快照
    用户选候选 → 初始化 LaunchInput → 显示可编辑字段
    用户修改 → 保存修改后的快照 → 校验并保存为新项目配置
```

扫描只读取安装线索，不启动找到的应用，不修改安装或原工作空间。路径存在不证明产品兼容；无结果、访问失败、发现器失败和超时必须可见。开发环境验收必须实际找到这台电脑上已知安装的应用并带入配置，不能只用假目录证明输出格式正确。

| 情况 | 用户应收到的反馈与后续动作 |
| --- | --- |
| 必填或格式不合法 | 字段附近提示，修正后提交 |
| 密码输入取消 | 取消本次启动，不创建进程 |
| 路径不正确、许可不可用 | 返回可定位的原因，修正配置或服务后重新操作 |
| 正在检查或等待窗口 | 同配置启动按钮不可重复提交，后台也检查重复 |
| 发现窗口 | 显示已观察到窗口，提醒在应用内核实登录 |
| 达到观察阈值仍无窗口 | 显示未确认，继续后台观察，不自动再启动一次 |

选择已有配置时，读取配置快照并初始化输入信息类，再让 ViewModel 展示；切换所选配置只更换编辑信息，不改变已提交请求或已运行进程。具体初始化与提交见⑤。

## ④ 必须保证什么：对象契约与执行规则（SRS）

| 对象 | 拟议内容与责任 | 明确不承担的责任 |
| --- | --- | --- |
| `LaunchInput` 输入信息类 | 每个编辑会话一份可变信息：配置 ID/版本、应用与许可引用、项目/用户/MDB/模块、密码策略；可由配置初始化或由界面显式赋值 | 不是 ViewModel；不实现绑定通知、命令或业务执行；不装入服务对象和明文密码 |
| `LaunchViewModel` | 显示字段、格式校验、错误提示、按钮状态、结果展示；提供输入导出和结果应用方法 | 不引用协调器或平台实现；不访问文件、凭据库、许可或进程；不在属性 setter 中启动业务 |
| `LaunchRequest` 请求快照 | 提交时复制输入，带 AttemptId、配置/关联版本和冻结字段；集合也复制为不可变值 | 提交后不再读可变 LaunchInput/输入框；不包含 WPF 类型和明文密码 |
| `LaunchCoordinator` 后端协调器 | 接收请求，校验业务条件，协调配置、许可、参数、秘密、进程及运行状态 | 不读取控件、DataContext、ViewModel，不负责界面布局 |
| `LaunchInteraction` 薄交互入口 | 被按钮事件显式调用，采集输入、请求密码、传参、转交结果和订阅状态 | 不拥有参数规则、许可策略和进程编排；不是另一份业务协调器 |

WPF 可以绑定 ViewModel 的显示字段与状态，但绑定本身不得调用后端；启动使用明确的 `Click → LaunchInteraction → LaunchCoordinator.ExecuteAsync`。后端依赖通过构造注入装配，业务输入通过请求参数传递，二者不混用。

执行约束：前端做必填/格式校验，后台仍验证业务和外部条件；每次启动使用独立子进程环境；密码不进入普通请求、预览、日志或分享；后台在 Checking/Starting 阶段按配置拒绝重复，前端禁用只是提示，不是唯一保护。配置版本不符时要求刷新，不擅自执行另一份组合。进程可能已创建而确认失败时返回“需核验”，禁止自动重试。

RunId 对应一次后台运行；AttemptId 对应一次提交意图，同一意图的重复调用在本次进程生命周期内返回已有结果或处理中状态。应用重启后的持久去重尚不承诺；遇到崩溃或不确定结果先人工核验。Running/Unconfirmed 后是否再次允许启动参照原行为单独验收，不把忙碌锁夸大为永久单实例约束。

**最低可验证性从第一步实现：** 扫描、编辑提交和启动各有关联编号，使用 `List<Record>` 保存顺序记录，同时用本机追加日志保存脱敏值快照；不只写“成功/失败”，也不等流程完成才补日志。快照必须复制数据，输入随后改变不能改写历史；日志用于复核，不自动重放操作。

## ⑤ 前端如何传参：信息与显示分开（前端 SDD／SDS）

**初始化和注入，拟议伪代码：**

```text
应用组合根启动：
    配置读取器 = 创建独立工作空间的只读查询能力
    后端协调器 = 注入配置、许可、参数、秘密、进程和运行状态能力
    交互入口 = 注入后端协调器、配置读取器、密码对话框、UI 调度器
    创建窗口与 ViewModel；绑定仅用于显示和输入
    将按钮 Click 连接到交互入口，不设置调用后台的绑定命令

打开页面或选中配置：
    snapshot = 配置读取器读取所选记录及关联版本
    input = new LaunchInput(snapshot)        // 信息对象，不是 ViewModel
    viewModel.Load(input)                    // 复制值用于显示和编辑
    页面保留本次编辑的 input；更换选择时替换它
```

**提交与结果返回，拟议伪代码：**

```text
按钮 Click → 交互入口.HandleLaunch：
    errors = viewModel.ValidateFields()
    若有错误 → 显示字段提示，结束
    input.Update(viewModel.ExportValues())   // 显式更新信息类，无后台调用
    request = input.CreateSnapshot(新的 AttemptId)
    若本次需要询问密码：
        secretHandle = 密码对话框取得临时秘密句柄
        取消 → 显示取消，结束；明文不写入 input/viewModel/request
    viewModel.MarkSubmitting()
    尝试：
        result = await coordinator.ExecuteAsync(request, secretHandle, 提交取消令牌)
        UI 调度器执行 viewModel.Apply(result)
    调用发生异常且无法确认副作用：
        显示需核验，保留 AttemptId，不自动用新编号重试
    最终：
        释放本次临时秘密句柄；解除界面提交标记
    如果 result 包含 RunId：
        建立页面生命周期内的状态订阅，不延长秘密句柄生命周期
        coordinator.ObserveAsync(RunId, 页面订阅取消令牌)
        每个状态事件 → UI 调度器执行 viewModel.Apply(event)

切页：取消页面订阅，不停止后台运行或观察
重新进入：查询最新 RunId/状态快照，订阅后续事件
```

秘密句柄是受控、短生命周期的对象；协调器仅在 `ExecuteAsync` 返回前使用，调用方最终释放，不能把它保存到后台长期观察任务。使用已保存凭据时由后台根据凭据引用获取秘密，不通过界面转存。保存新密码是明确的配置保存操作，界面清空密码控件不能被当作“已清除所有内存副本”的保证。

设计理由：输入信息类隔离业务信息与 WPF，ViewModel 保留即时反馈，请求快照固定一次执行的含义；薄入口提供可见调用位置，避免属性变化触发副作用。代价是输入/显示间需要显式映射，必须测试字段完整性。不能为省映射代码让协调器反向读取 ViewModel。

前端需求入口为③④，设计入口为本股，未来代码入口为⑦的 `Desktop/Features/Launch`；评审无需打开源码即可理解初始化、采集和回显。

## ⑥ 后端如何执行：协调基础能力并返回事实（后端 SDD／SDS）

**执行与返回，拟议伪代码：**

```text
ExecuteAsync(request, 临时秘密句柄, ct)：
    原子登记 AttemptId 与请求摘要：已有相同请求 → 返回已有回执或处理中
    同号不同内容 → 拒绝，不覆盖原请求
    获取配置级准入：该配置正在 Checking/Starting → 返回 Busy
    读取应用/许可/工具关联，核对请求中的版本，冻结本次执行所需数据
    后端校验字段、路径、工作目录和入口协议；失败 → Rejected
    检查许可启用与连接状态；失败 → Rejected
    构造参数计划与独立子进程环境；冲突或非法参数 → Rejected
    解析秘密：使用临时句柄或本机凭据引用；取消/缺失 → 不启动
    各阶段即时保存输入、校验和脱敏计划，失败出口也记录原因
    在进程创建前检查取消，保存创建意图并确认前序必要记录已落盘
    必要记录保存失败 → 不创建进程，返回证据保存错误
    尝试创建一次进程：
        明确未创建 → 返回 Failed
        创建结果不确定 → 返回 NeedsVerification，不自动再创建
        已创建 → 分配 RunId、登记跟踪句柄与 Starting 状态
    将观察职责移交后台运行注册表；清理执行所用秘密
    若创建后登记/移交失败 → 返回 NeedsVerification，保留已知 PID 等诊断
    成功 → 返回 Created(AttemptId, RunId, 最新状态)
    在所有创建前失败出口释放准入；创建后由状态归约管理准入

后台观察任务：
    读取入口、子进程和窗口证据 → 更新状态快照并发布事件
    状态转换和错误追加 Record 与日志，重复轮询不重复保存相同快照
    窗口出现 → WindowObserved；超过阈值无窗口 → Unconfirmed，继续观察
    已跟踪进程全部退出 → Exited；明确失败 → Failed
    离开 Checking/Starting 时释放启动准入；失败/退出时释放跟踪资源
    页面订阅取消不影响该任务；停止观察不强杀目标应用
```

`LaunchResult` 返回状态码、AttemptId、可选 RunId 和不含秘密的原因；`Created` 只证明进程创建，不证明窗口或登录。`ObserveAsync` 先返回最新快照，再提供带 RunId/递增序号的事件，界面忽略旧序号，避免订阅间隙丢失当前状态；具体队列实现由独立设计与测试决定。

| 基础能力（拟议） | 输入 → 输出／职责 | 采用理由与代价 |
| --- | --- | --- |
| `WorkspaceReader` | ID、预期版本 → 配置及关联快照／冲突 | 拒绝界面编辑期间发生的配置漂移；需版本管理 |
| `LicenseProbe` | 许可设置 → 就绪证据／原因 | 启动前发现不可达，不把连接等同签出；重试策略必须显式 |
| `LaunchPlanBuilder` | 冻结字段、入口协议、环境 → 无明文秘密的参数计划 | 参数为纯规则，便于用例测试；Monitor/Marine 保留各自字符和引号规则 |
| `SecretProvider` | 凭据引用或临时句柄 → 执行期秘密 | 秘密不流经通用 DTO；需要明确释放和生命周期 |
| `ProcessGateway` | 参数计划、秘密、环境 → 创建结果、跟踪句柄及观察证据 | OS 副作用集中，方便隔离验证；不能用模拟测试声称厂商环境可用 |
| `RunRegistry` | AttemptId、RunId、状态与句柄 → 回执、当前状态、事件 | 后台拥有运行生命周期，切页不失联；本阶段为进程内状态，崩溃恢复未承诺 |
| `RecordLog` | 脱敏值快照 → `List<Record>` 与本机 JSONL 日志 | 第一版直接提供可读证据，不需要数据库或日志平台 |

`RecordLog` 是责任名称，不表示必须手写日志基础设施；JSONL 是候选落盘形式。先评估 NLog 等现成库，再比较最小 .NET 实现；输入校验/通知可评估 CommunityToolkit 的适用组件，测试及断言库也应提出候选。用户已批准主方案的具体包及版本，见[依赖评审表](dependency-review.md)；新增或变更选型才需要补充评审。批准不代表已经安装或验证。库不能改变 ViewModel 不调用后台、快照不含秘密和写入失败可见的契约；不能以引入库替代行为测试。

**记录形状与保存，拟议最小实现：**

```text
Record = { CorrelationId, Sequence, UtcTime, Stage,
           Snapshot, Outcome, ErrorCode }
Records = new List<Record>()

SaveRecord(stage, data, outcome)：
    snapshot = 只复制允许记录的字段，移除密码、秘密句柄和敏感变量值
    在本次操作的串行写入区内：
        record = 新建带递增序号的不可变 Record(snapshot)
        Records.Add(record)
        Log.AppendJsonLine(record) → Flush
        写入失败 → 标记“证据未持久化”，向调用方返回错误
```

记录应在各阶段发生时追加：启动保存输入、校验结果、许可摘要、脱敏计划、创建意图、创建结果/PID、状态变化和结果；失败出口同样记录原因。扫描保存发现器及配置版本、范围、候选与诊断，人工修改保存前后值和来源。只保存安全摘要，不倾倒含秘密的命令行、环境或脚本输出。日志按关联编号写入新项目数据目录 `logs/`，供人工查看与测试断言。

内存追加不等于落盘成功：创建前必要日志失败则不启动；创建后写入失败保留内存事实并返回“需核验”，不重开进程补偿。重启可查看完整落盘记录，但不承诺自动续跑、断电零丢失或永久去重。保留/清理策略需明确，不默默删除诊断证据。

Monitor 计划走原生参数列表；Marine 计划遵循批处理可原样传递的词元限制，秘密仅在平台交接时展开；子环境注入许可地址与关联工具变量，不改全局许可。这里是需要在新代码证明的设计，不是引用旧类即自动满足。

后端需求入口为④，设计与契约在本股，拟议实现位于⑦的 Application/Domain/Platform。许可重试次数、观察阈值等可参考原值，但配置策略和兼容矩阵须在实现任务中确认；参考值不当成 SLA。

## ⑧ 怎样验收和维护：证明边界而不是数八个标题

| 场景 | 应能证明的结果 |
| --- | --- |
| 初始化及字段映射 | 配置 → LaunchInput → ViewModel → Request 不漏字段；提交后修改界面不改变快照 |
| 本机发现与预填 | 实际找到本机已知安装，记录搜索范围和候选路径；预设可改、多结果可选、重扫不覆盖人工配置；未找到如实失败 |
| 快照与日志 | 修改输入不改变 Record；关联与顺序正确；重读 JSONL 能复核正常/失败流程；创建前写入失败不启动，创建后失败不重开 |
| 绑定与调用边界 | 修改属性不启动业务；ViewModel 无协调器/平台依赖；Click 显式调用入口 |
| 前端校验被绕过 | 后台仍拒绝无效参数、过期配置与未就绪许可 |
| 重复与不确定结果 | Checking/Starting 阶段后台拒绝同配置重复；同 AttemptId 重入不创建第二次；不确定结果不自动重试 |
| 秘密与环境 | 密码不进普通 DTO/日志/分享；不同配置子环境隔离；取消输入不创建进程 |
| 结果与页面生命周期 | Created 不显示为登录成功；订阅先取最新状态；切页不停止观察；旧事件不覆盖新事件 |
| 原 UI 行为参照 | 核对布局、按钮、密码交互和状态含义；差异明确提出，不因新代码静默改变 |
| 架构与设计基线 | ArchUnitNET 守卫必须拦住违规反例；FigCraft 预览与原视觉基线核对；均不替代运行行为验证 |
| 真实应用验收 | 分开验证参数交接、窗口观察、实际登录与许可签出；隔离进程测试不替代厂商环境 |

六类文档答案就在①—⑧：收益与边界、能力范围、操作流程、约束验收、前后端结构和契约。正式化拟以本 Feature 正文作为唯一事实源，六类索引只链接相应股，DocFX 展示同一内容；跨 Feature 共性才抽取到 decisions。OpenSpec 与正文通过稳定标识关联，避免同一要求分别维护两段权威正文；具体生成方式由文档任务提出并校验。
