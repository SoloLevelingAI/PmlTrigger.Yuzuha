# WPF M1 实机走查

## manual:desktop-aveva-m1

状态：NotRun。本机合成截图和离线 Host 测试不能代替此案例。

环境：安装了匹配 Host 的 AVEVA NET35 或 NET48 测试会话；仅使用自有测试文件与目录，不保存工程。

1. 启动 WPF。发现会话，确认没有自动选择。选择实际目标，核对项目、PID、启动时间、模块与 Host 能力。未发现 Host 时查看提示，再通过已有交付方式更新 Host 并重新发现。
2. 使用仓库 `tests/live/form-query` 的独立测试文件和说明。开发来源保留在已注册 PMLLIB 之外；部署测试副本与实际加载各自留记录。不修改厂商原生文件。
3. 在能力与函数页登记一个自有全局 `.pmlfnc`。核对真实声明、完整 SHA256 和参数顺序。确认首次登记拒绝调用，授权后可预览。执行一次并记录真实请求编号；调度结果不等于业务返回值。
4. 修改自有源文件后再次调用，应在发送前拒绝。重新登记应撤销许可，人工授权后才允许再次调用。登记不会加载 PML；加载状态单独核对。
5. 查询已显示/已加载窗体，选择测试窗体，再读取控件与属性。检查 MENU 和普通成员未混入、原生索引保留、空文本与 unavailable/null 区分。读取现有数组并按 NextIndex 续读；改变预算后要求开始新查询。
6. 让测试会话退出或选择无 Host 的候选，确认旧结果不再作为有效目标。超时或发送后取消时保留结果未知，不自动重试。不得为制造故障结束用户工程进程。
7. 在 1280×720、150% 系统缩放下用鼠标与键盘完成上述任务。检查焦点、滚动、完整错误定位和返回后的输入保留。记录求助、误解与阻塞点。

预期：三条流程可独立完成；没有选错目标、绕过许可、将历史/未知当通过或保存工程。记录本次提交、dirty、环境、目标启动身份、源码/部署哈希、步骤、请求编号和本机证据路径；无法完成的步骤明确保持 NotRun。
