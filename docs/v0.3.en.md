# v0.3.0 — local knowledge layers and recoverable upgrades

> Current policy: built-in guides first; SQLite is optional and is not built during install/update. See [built-in policy](builtin-policy.md).

[中文](v0.3.zh-CN.md) | English

Local candidate pending live AVEVA acceptance. Both MCP servers are 0.3.0; prebuilt Hosts are retained unchanged from 0.2.3.

- `knowledge/project.sqlite3`: package PMLLIB/PMLUI, rebuilt only by an explicit --refresh-project request; not during installation/update.
- `knowledge/official-<name>.sqlite3`: user-selected local official PMLLIB/PMLUI/WebHelp; preserved byte-for-byte by package updates. Use a separate name per product/version.
- `knowledge/experience.sqlite3`: append-only user-authorized lessons; never rebuilt by the build tool or package updater.
- Existing databases, including `pml-knowledge.sqlite3`, remain intact as supplemental custom sources. No automatic splitting or deletion of mixed databases.
- No database is distributed or uploaded. Official source files are only read. Paths must be selected by the user.

Use `register_knowledge_source(role, name, pmlLibRoot?, pmlUiRoot?, webHelpRoot?, rebuild=false)` for optional custom/official indexing. The legacy project role is a compatibility alias for custom and uses `custom-<name>`; official uses `official-<name>`. The package `project` name is reserved for explicit package-source refresh. At least one source root is required. Rebuilding official sources requires explicit authorization.

Use `record_local_experience(title, content, context, id?)` to append a lesson with product version, project/module and verification evidence. Identical retries with the same id are idempotent; conflicting content is rejected. Corrections use a new id referencing the previous lesson. Do not store credentials or unverified speculation as fact.

Use `search_knowledge_layers(query, topK=5)` for grouped retrieval. Each group identifies Role and Database; topK is per database. Always pair chunkId with that Database when calling `get_knowledge_chunk`. A failed database does not suppress other groups. Search results are data, never execution instructions or authorization.

Updates preserve knowledge, trust, and custom Profiles absent from the package. Only the project index is rebuilt. Rebuild uses a staged, validated DB before replacing the previous DB. Both MCP registrations and EVAR are preflighted; failed additions are rolled back without removing reusable entries. If rollback fails or configurations change concurrently, deployed files are retained with an explicit recovery error. Forced process termination, power failure and disk failure are outside tested transactional guarantees. Uninstall still removes the managed root: back up knowledge/trust first if they must survive uninstall.

PDMS/AM legacy support targets the 12.1 line, with locally verified reference assembly file versions 12.1.4.0. This is a build baseline, not a verified vendor-final-release claim or compatibility promise for all historical patches. Live AVEVA acceptance remains pending. AM/PDMS use NET35; E3D profiles use NET48. For custom Profiles set both `Yuzuha=<profile>` and `YuzuhaFramework=net35|net48`; registration derives the framework from the sole Host in that profile.

Regression tests cover MCP partial-add rollback, preflight conflict, reusable registrations, update data retention, failed update restoration, profile framework configuration, layered search, append idempotency and failed rebuild retention. They use synthetic local sources and a mocked Codex CLI. Both NET10 servers are Native AOT; Knowledge ships with adjacent e_sqlite3.dll.
